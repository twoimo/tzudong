# 맛집 관리와 최신화 통합

맛집 최신화를 맛집 관리의 `최신화·이력` 탭으로 통합했다. 별도 메뉴를 제거하고 저장된 사이드바 순서는 통합된 항목만 제외한 나머지 순서를 유지한다. 기존 `module=restaurant-refresh-history` 주소는 `module=restaurants&restaurantView=refresh`로 연결하며 기존 영상·사유 필터를 보존한다. 검수·최신화 탭은 URL로 선택 상태를 유지한다.

사용자가 지목한 설명 문장과 반복 배지·단계 안내·빈 상세 설명을 제거했다. 후보가 선택되기 전 빈 상세 영역은 표시하지 않는다. 후보 선택·결정·적용 확인, 관리자 권한, 폐업 후보 자동 적용 차단은 유지한다. 탭과 패널의 접근성 ID를 연결하고 방향키로 양방향 전환을 확인했다.

합성 데이터에서 1440×1000, 390×844, 834×1194의 가로 넘침은 각각 0px였다. 모바일 선택 탭 높이는 44px이다. 메뉴는 14→13개(−1개·−7.14%). 데스크톱의 선택 전 목록 폭은 660.390625→1158px, 차이 +497.609375px·+75.350763%였다. 이 값은 고정된 한 뷰포트의 결정적 기하 측정(n=1)이며 모집단 추정이나 속도·생산성 개선을 뜻하지 않는다. 기하 조건이 고정된 값에 표본 기반 95% CI를 만들어 붙이지 않는다.

관련 검증 63개, 전체 웹 2,661개 통과·9개 건너뜀·실패0, TypeScript native/compat parity, Next16.3.8 운영 번들 47페이지 생성을 통과했다. 필수 CI와 운영 적용은 계속 확인한다. 화면은 합성 localhost이므로 운영 배포·사용자 데이터 검증 증빙이 아니다. 네이티브 캡처가 이전 프레임을 반환한 경우는 기각하고 실제 뷰포트와 일치한 `tab.screenshot` 픽셀을 사용했다.

소스 카탈로그의 별도 문제도 복구했다. 20260820 배치 저장 소스가 회수한 식별자 보조 함수 3개의 service_role 실행 권한을 새 `20261003095444_restore_service_identity_helpers.sql`로 재구성한다. 운영에는 이미 같은 권한이 있어 적용 전후 ACL digest `464bd30c9e382b19dd7a638cc3b626a2`가 일치했다. 일반 사용자·비로그인 실행은 허용하지 않는다. 기존 적용 SQL은 수정하지 않았다.

깨끗한 소스 재생에서는 복구 파일을 등록 검증 파일보다 먼저, 각각 정확히 한 번 실행하는 의존 순서를 명시한다. 이 순서는 과거 운영에서 선행했던 권한 복원을 소스로 재현하며 기존 권한 검증을 약화하지 않는다. 격리 DB 검증 10개와 실제 Bash 순열·선행 관계 검증을 통과했고, 전체 카탈로그 재생은 CI에서 확인한다.

증빙은 `apps/web/performance/ui-renewal-20261003/restaurant-management-*`, `service-helper-permissions-hosted.json`, `service-registry-local.json`에 있다. 전체 장기 목표는 계속 활성 상태이며 실제 운영 적용·완료 감사를 대체하지 않는다.
