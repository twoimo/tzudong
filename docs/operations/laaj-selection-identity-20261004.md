# 평가 재시작·위치 근거 바인딩 · 2026-10-04

기본 순차 및 OAuth 평가가 병렬 경로와 같은 영상별 잠금을 사용하도록 연결했다. 잠금은 완료 기록 확인부터 결과/완료 기록 저장까지 유지한다. 단일 작업의 첫 API 실패 뒤에는 남은 영상도 기존처럼 OAuth로 전환하며, OAuth는 공유 잠금으로 순차 처리한다. 한 실행의 API 작업을 마친 뒤 OAuth를 수행한다. 다른 실행의 API 작업과 OAuth가 겹치지 않는다는 보장은 이 검사 범위에 포함하지 않는다. 전체 임시 폴더는 실행마다 분리했다. 정상 입력의 모델·프롬프트·결과 형식과 영상 한도는 유지한다. 초기 API health probe는 별도 수행하지 않고 실제 평가 요청이 성공 여부를 결정한다. OAuth의 기존 확인 경로는 유지한다.

POSIX에서는 영상·OAuth 잠금 파일 descriptor를 자식에게 상속해 잠금 소유 프로세스가 SIGKILL되어도 살아 있는 평가 자식이 끝나기 전에 다음 작업이 진입하지 못하게 했다. Windows의 해당 강제 종료 보장은 이번 검사에 포함하지 않았다. 오류 출력은 고정 코드로 제한하고 공급자 진단 원문을 터미널에 출력하던 경로를 제거했다.

선정이 평가 미대상으로 바뀌면 이전 rule/LAAJ 결과와 완료 기록을 각 단계의 `.superseded`로 이동한다. 원본 바이트를 보존하고 활성 glob에서 제외하며 새 분류 저장이 끝날 때까지 하위 단계 잠금을 유지한다. 완료된 미대상 선정의 재사용 때도 남은 활성 결과를 정리한다. rule 작업은 선정→rule 순서로 잠근 뒤 입력을 다시 읽으므로 삭제된 선정의 옛 메모리 값을 결과로 게시하지 않는다. transform의 기존 전체 입력 검증과 단일 작성자는 유지한다.

자동 승인에는 위치 평가의 `origin_name`이 현재 맛집의 `origin_name`과 일치하는 문자열이라는 조건을 추가했다. 누락·잘못 연결된 지점 근거는 `hold:location_identity_mismatch`이며 다른 승인 조건을 충족해도 승인하지 않는다. 삭제된 과거 행은 대체 맛집의 중복 조건에서 제외하고 활성 행의 중복 조건은 유지한다. 적용된 함수 파일을 수정하지 않고 새 `20261004010334_restaurant_review_identity_evidence.sql`로 알려진 함수 본문만 패치한다. 소유자·ACL·invoker·search_path·volatility가 동일함을 확인하고 본문이나 anchor가 다르면 전체 rollback한다. 운영 함수 본문 해시는 읽기 전용으로 확인했으며 새 SQL은 아직 적용하지 않았다.

실제 셸의 기본 모드 동시 실행 2개에서 모의 평가 요청 1회·출력 1행을 확인했다. POSIX 소유 프로세스 강제 종료 실험에서도 두 번째 작업은 살아 있는 자식의 잠금 해제까지 기다렸고 실제 작업은 1회였다. 이론적으로 동시 동일 작업 n개는 유효한 완료 기록과 잠금 안의 확인을 통해 실제 평가 작업 1개로 합쳐진다. 관찰은 n=2·각 시나리오 1회이며 실제 공급자 지연·토큰·금액 절감이나 모집단 신뢰구간은 주장하지 않는다.
