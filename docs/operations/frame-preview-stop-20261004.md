# 프레임·미리보기·중지 경계 검증 · 2026-10-04

배치 프레임 수집의 완료 표시와 폴더 존재 검사를 실제 완료 기록 검증으로 바꿨다. 캐시 영상의 바이트 해시, ffmpeg·구현 해시, 세그먼트 시간·FPS·화질·포맷과 현재 출력 해시가 모두 일치할 때만 재사용한다. 캐시 소스나 완료 기록이 없거나 손상·설정 변경이 있으면 작업을 통과시키며 기존 Shorts·수집 일정·처리 한도는 유지한다. 히트맵이 바뀌지 않았다는 이유로 프레임 검증을 건너뛰던 경로도 제거했다. admission과 추출이 같은 probe/hash 함수를 사용한다.

정상 재사용의 검사에도 로컬 영상 해시와 ffprobe 비용이 추가된다. 캐시 파일 바이트를 검증하며 제공자가 원격 영상을 몰래 바꿨다는 사실까지 확인하는 검사는 아니다. 캐시가 없는 기존 완료 표시를 다시 검증하려면 다운로드가 필요할 수 있다. 이 스캔·다운로드 비용과 전체 파이프라인의 처리량은 아직 측정하지 않았으므로 속도·금액 절감은 주장하지 않는다. 실제 ffmpeg의 출력 동등성과 재사용·부분 손상 복구·실패 기록 보존 검사는 통과했다.

caption은 현재 프레임만 입력으로 사용한다. 숨김 보관·임시 폴더를 순회 전에 제외하고 심볼릭 링크 파일도 제외한다. 5개 합성 이미지 중 활성 2개만 선택했으며 보관/임시 이미지가 입력에 들어간 수는 0개다. 입력 집합 \(A\)는 전체 파일 집합 \(F\)에서 비활성 보관 집합 \(H\)를 뺀 \(A=F\setminus H\)다. caption 추론·모델 정확도와 실제 비용은 이 검사에 포함하지 않았다.

저장 미리보기는 실제 적용과 같은 보호 snapshot·변경 없음 판정을 먼저 수행한다. 기존과 같은 첫 행은 미리보기/적용 모두 건너뛰고 다음 변경 행이 같은 한도 안에서 선택된다. 검사에서 변경 없음 1건·변경 대상 1건이 양쪽에서 같았고 미리보기 DB 쓰기는 0회였다. 기존 CAS·관리자 보호·저장 readback은 유지한다.

메타데이터의 처리 recipe가 바뀌면 메타가 같고 수집 일정이 없어도 해당 recipe 처리를 실행한다. 이전 광고 분석 결과를 다른 recipe로 재인증하지 않고, 실제 분석과 저장을 거친 결과만 새 체크포인트로 확인한다. 확인 뒤 같은 입력을 다시 실행할 때는 공급자 메타 조회 0회였다. 실패한 분석은 새 체크포인트를 게시하거나 이전 메타데이터를 교체하지 않는다. 정상 응답의 `None` 판단과 공급자 실패를 구분한다. 기존 모델과 사용 한도는 바꾸지 않았다.

중지는 맛집 분류나 전체 테이블 용량에 의존하지 않는다. 미리보기에서 실행만 50,000건 용량 제한을 확인하며 중지는 정책·대기열의 현재 상태를 사용한다. 50,001건 합성 행을 추가한 격리 PG17.6에서 실행 미리보기 거부, 중지 미리보기 성공, 적용 후 정책 꺼짐·대기/실행 작업 0건을 확인했다. Preview→Confirm→Apply→Readback 구조와 stale preview 거부는 유지한다. 변경한 manual guard SQL은 아직 운영 미적용 원본이며 이미 적용된 migration은 변경하지 않았다.
