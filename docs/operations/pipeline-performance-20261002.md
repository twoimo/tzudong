# 크롤링·검수 최적화: 구현과 운영 적용안

완료 범위는 격리된 후보의 구현·검증·운영 적용 준비다. 운영 DB 마이그레이션, 배포, 원본 데이터 변경은 수행하지 않았다. 기존 모델과 hosted apply 차단을 유지한다.

## 수학적 모델과 실측

성능 증빙은 `apps/web/performance/pipeline-20261002/`에 있다. `summary.json`은 전후 절대값, 변화율, 짝지은 bootstrap 95% 구간과 노이즈 기준을 포함한다. 최초 탐색 실패도 `transform-rejected-v1.json`에 보존했다.

| 구간 | 통계·표본 | 변경 전 → 후 | 변화율·95% 구간 |
|---|---|---|---|
| 변환: 변경 없는 재실행 | p75, 7쌍 | 539.53 → 257.84 ms | 52.21% 감소 [49.30, 53.03] |
| 변환: 입력 5개 변경 | p75, 7쌍 | 전체 재구축 581.51 → 증분 447.25 ms | 23.09% 감소 [20.23, 24.66] |
| 변환: 최초 실행 | p75, 7쌍 | 537.88 → 853.47 ms | 58.67% 증가 [48.14, 65.28] |
| API 직렬화·소비자 처리 재생 | p95, 100쌍 | 13.15 → 0.94 ms | 92.84% 감소 [89.91, 93.94] |
| API 응답 원문 | 동일 데이터 | 4,905,647 → 163,824 bytes | 96.66% 감소 |
| API 응답 gzip | 동일 데이터 | 937,532 → 23,115 bytes | 97.53% 감소 |
| 반복 공급자 읽기 재생 | p75, 7쌍 | 758.75 → 41.00 ms | 94.60% 감소 [94.34, 94.82] |
| 공급자 읽기 시도 | 요청 500개·서로 다른 키 25개 | 500 → 25 | 95% 감소; 실제 네트워크 호출 0 |

변환 캐시는 최초 인덱스 구축 비용을 지불한다. `N × 재실행 절감 > 최초 추가 비용`이므로 p75 기준 변경 없는 재실행 2회부터 최초 비용을 회수한다. 최초 실행의 회귀를 숨기거나 전체 실행이 빨라졌다고 주장하지 않는다.

읽기는 입력·설정 해시로 재사용하며, 파일 상태 서명 `(device,inode,size,mtime,ctime)`이 달라지면 내용을 다시 해싱한다. 전체 변환 출력 해시가 달라지면 기존 인증을 재사용하지 않는다. 원본 3,307개 파일·23,636,539 bytes의 SHA-256 전후 일치와 변환 1,257건의 전체 결과 해시 일치를 확인했다.

검수 목록은 50건(최대 200건)과 커서를 반환한다. 통계와 동일 영상 경고는 전체 인덱스를 대상으로 계산한다. 정규화·검색·상태 분류를 서버와 UI가 공유하며, 데이터 버전 변경 시 커서를 폐기한다. 상세 근거는 선택 시 조회한다. HTTP 응답은 private/no-store이며 두 새 RPC는 service_role만 호출할 수 있다.

## 검증과 한계

웹 단위 2,620 통과·9 skip, 오케스트레이션 213 통과, 관련 Python 계약·캐시 검사, Node 유틸리티 11 통과, native/compat 타입 검사와 대상 ESLint를 검증했다. PostgreSQL 15.8의 독립 테스트 DB에서 일반·인증 역할 거부, 수정·삭제 갱신, 롤백 보존, 검색 카운터만 변경했을 때 인덱스 보존을 확인했다. 로컬 브라우저 fixture 100회는 오류 0이며 첫 페이지 밖 검색과 상세 조회, 모바일·데스크톱 렌더링을 확인했다.

이 수치는 로컬 실험이다. API 재생에는 실제 DB·네트워크 지연이 포함되지 않는다. 공급자 재생은 1ms의 통제된 응답을 사용한다. 브라우저는 dev 서버의 합성 데이터이며 변경 전 화면 지연과 비교하지 않았다. 24시간 운영 관측과 완전한 G003 scorer/validator 증빙이 없어 공식 운영 개선, 실제 금액 절감, 세계 순위, 실제 ML 정확도 향상을 주장하지 않는다.

## 운영 적용 순서

1. 현재 후보를 검토하고 보호된 `develop → data → main` 순서로 소스를 승격한다. 이 작업에서는 승격하지 않았다.
2. 새 `20261001172315_admin_evaluation_pagination.sql`을 프로젝트의 정식 로컬 replay와 운영 preview/readback 절차로 적용한다. 기존 마이그레이션은 수정하지 않는다. RPC가 없는 상태에서 새 페이지 조회를 배포하지 않는다.
3. 기존 Python 가상환경·Node 24·npm 11.6.2와 잠금 파일을 사용한다. 기본 추론 동시성은 1이다. 실제 프로젝트 제한을 확인한 뒤 `GEMINI_MAX_INFLIGHT`(1–8), `GEMINI_REQUESTS_PER_MINUTE`, `GEMINI_BUDGET_PROJECT`를 설정한다. API 키 수나 CPU 수를 쿼터로 해석하지 않는다.
4. `PIPELINE_FFMPEG_JOBS`와 `PIPELINE_NETWORK_JOBS`는 별도 상한이다. 중첩 프레임 작업은 공유 풀을 사용한다. 워커가 소유한 미디어 캐시는 성공 후 제거하고 실패 시 재시작용으로 유지한다. 기존 사용자가 지정한 캐시는 삭제하지 않는다.
5. 배치 크기는 `PIPELINE_RESTAURANT_BATCH_SIZE` 1–200으로 설정한다. live item 제한은 유지하며 동일 행은 저장하지 않는다. 관리자 보호·조건부 갱신·읽기 확인과 불확실한 저장의 재전송 금지는 유지한다.
6. 운영 후보의 롤백 SHA와 적용 후 SHA·URL을 새로 확보한다. 현재 source/test 증빙을 운영 readback으로 사용하지 않는다.

## 크레딧 추가 요청

사용자 지시에 따라 Google One 혜택 6 × US$10을 기존 활성 `내 지도 결제 계정 2`에 적용했다. 새로고침 후 GCP 잔액은 앱에서 약 ₩8.15만으로 표시된다. 선불 잔액은 0, 자동 충전과 미래 혜택 자동 적용은 꺼져 있다. 현금 충전과 `tzudong-free-zero` 결제 연결은 수행하지 않았으며 추가 승인 대기다. 코드·키·카드 정보는 이 문서에 보관하지 않는다.
