# Prospective anonymous Web Vitals

Production root documents collect the first visible window of classic CLS, INP and LCP with the existing `web-vitals` dependency. Each metric instance is sent once; later resumed-tab updates of the same metric are not appended. BFCache metric instances are excluded pending validation of the pinned6.1.1 CLS restoration behavior. Missing INP without an eligible interaction is not a zero. Initial viewport class stays fixed for the document.

The application payload contains only version, mobile/desktop class, metric name, navigation class, fixed bucket and build Git SHA. It never contains metric/user/session IDs, URLs, query values, precise location, UA or metric entry objects. Requests omit credentials and Referer. Ordinary provider HTTP processing remains outside the stored aggregate payload. Automated, preview/local, private initial pages and explicit `__qa`/`__perf*` documents are excluded. All hosted browser checks must open with `?__qa=render-flow` before navigation to avoid contaminating the production cohort.

The server requires the client build Git SHA to equal the serving release (old documents crossing a deployment return409 and are excluded), then binds the UTC day, then atomically increments a histogram count in the existing Supabase project. RLS and revoked grants deny browser roles; only the server service role can call the SECURITY INVOKER RPC. No personal-data retention class or policy is activated or changed. Provider request processing still has its existing network/security boundaries; this document makes no legal-compliance certification.

INP bins are16ms, LCP100ms, CLS0.01. Overflow starts at3200ms/12000ms/1 respectively. Quantiles return interval bounds, including open-ended overflow, never false exact values. Counts are metric samples, not distinct users. Compare release cohorts with the same metric/device/navigation eligibility; retain sample counts, day coverage, distribution/quantile intervals and calendar/network/provider uncertainty. Do not attribute a low-sample or QA-contaminated difference to a release. Daily block uncertainty requires adequate independent days; no user independence or user p95 is invented.

A collecting deployment starts the prospective Before cohort; a subsequent memory change creates the After cohort. Installation/readback/QA validation are distinct from real-user improvement. Empty cohorts remain pending. Collection adds at most3small credential-omitted requests per metric lifetime and no React state update. Histogram writes/errors have fixed bounds and codes; no raw provider/request diagnostic is logged.
