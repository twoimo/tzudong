# 실제 마커·근거 프레임 연결 및 전달 계획
사용자 지시: 실제 데이터로 국내·해외 불 효과와 상세 패널의 여러 근거 프레임을 연결하고 PC·모바일·태블릿 검증 후 보호 배포한다. Nightly는 별도 기록한다.
소스 기준: 13ded67a820549ae51f5b966104bf900c22aeb1a. 실제 운영 rollback 기준은 배포 직전에 재확인한다.
기존 thesis: cursor-evidence-cross-audit-20261018-v2/MASTER-PLAN-v3.md 및 그 원문 연구를 재사용한다. 이번 내용은 미발행/미적재 경로에 관한 추가 변경이며, 과거 배지 검사나 연구 완료로 검증을 대체하지 않는다.

관측: 공개 등급 entries=0, 운영 프레임=0, 영상 분석행2277개, 승인 식당763개. Drive에는 기존 영상별 실제 추출 JPG가 있으며 파일명에 밀리초 수준 시각이 보존된다. 이미지와 영상 ID·식당 ID·해시를 대사한다. 썸네일을 실제 장면으로 대체하지 않는다.

실행 순서와 수용 조건:
1. 기존 병합 규칙으로 승인 식당 그룹을 고정하고, 공개 영상 KPI의 관측값/관측일을 보존한다. 불/무지개 표시는 맛 평가가 아니라 연결 영상 조회수의 공개 스냅샷으로 한정한다. 새로운 복합 점수·감쇠 계수·private shadow 복사는 쓰지 않는다.
2. 후보 공개 정책은 국내/해외 지도별 그룹의 가장 많이 본 연결 영상 조회수로 nearest-rank P95/P85를 나눈다. 유효 양수 지표가 없는 그룹은 standard다. 전체 구성원 ID를 동일 등급으로 발행하고 출처·cutoff·결측·시점·해시를 별도 보존한다. 이 정책은 추가 교차 감사의 검토 대상으로 남긴다.
3. 동일한 CSS/SVG 불 효과를 네이버/해외 개별 마커에 연결한다. 지도 이동 중 정지, reduced-motion, 선택 확대, 기존 핀·클릭·SDK anchor를 보존한다. 등급 변경 시 기존 마커도 갱신한다. 마커당 WebGL은 추가하지 않는다.
4. 실제 프레임은 원본 바이트/Drive ID/영상 시각/기존 승인 식당 연결을 확인한 뒤 불변 WebP와 검토 manifest를 만든다. 원본 OCR·개인정보·credentials는 산출물에 넣지 않는다. 검토된 이미지의 WebP 키/해시를 protected Git으로 전달하고, 서버 전용 게시 도구와 동일한 manifest를 써서 canonical restaurant_evidence_frames에 대사·적재·readback한다. 다른 DB 행을 수정하지 않는다.
5. DB 스키마에 없는 image_url을 임의 요청하지 않고 정본 키에서 자체 호스트의 이미지 경로를 만든다. 실제 image_url이 있는 승인 자료도 기존 검증을 유지한다. 승인 간판/공식 위치 자막은 기존 L1 정의를 그대로 유지한다. 승인된 on_site_scene/menu_receipt는 별도의 맥락 장면으로 명시하며 L1 또는 단독 신원 증거로 승격하지 않는다.
6. 합성 테스트는 키 변조·잘못된 영상·승인 전·충돌·XSS·tier 갱신을 검사한다. 실데이터 검증은 공개 cohort와 실제 WebP/DB readback을 사용하고 카드 여러 장의 이미지 decode/시크 링크·스크롤·PC1440/태블릿820/모바일390 viewport·reduced-motion을 확인한다. 물리 iPad/폰 검증과 혼동하지 않는다.
7. 최종 소스의 관련 unit/lint/native+compat parity/production build, 필요한 실제 브라우저 확인을 수행한다. 실제 외부 delta 및 GPT reverse 보고서는 전문/hash/URL/모드로 저장하고 유효 지적을 해결한다. 완료되지 않은 외부 검증을 통과로 쓰지 않는다.
8. feature PR -> develop -> data -> main 보호 절차와 필수 검사를 따른다. 운영 exact-SHA/READY/alias/실제 이미지·국내/해외 마커·패널을 다시 확인한 뒤만 배포 완료다.
9. Nightly는 별도 evidence 파일로 실제 조회/실행한 범위만 기록하고 release 검증 결과와 합산하지 않는다.

데이터 범위와 잔여 위험: 존재하는 승인 식당 연결만 사용한다. 프레임이 없는 매장의 영상 썸네일을 근거로 꾸미지 않는다. 최초로 실제 게시한 식당/프레임 수와 전체 승인 식당 대비 coverage를 명시한다. 과거 메모리/실기기/field/flicker 목표를 이 기능 배포로 완료 처리하지 않는다. 수집 시점이 오래된 KPI는 UI와 보고서에 기준을 밝힌다.
