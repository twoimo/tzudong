3. REV-F-01의 남은 조건

현재 소스와 fixture가 입증하는 범위는 다음과 같다.

제거된 과거 루트가 반환돼도 이를 ready 상태로 오인하지 않는다.

다음 microtask에서 연결된 새 루트에 앱 소유 aria-hidden을 적용한다.

release 또는 visible 전환 시 pending observer를 취소한다.

기존에 다른 주체가 설정한 aria-hidden을 임의로 제거하지 않는다.

기존 리뷰 버블만 교체할 때는 루트의 숨김 상태를 유지한다.

그러나 MutationObserver 콜백의 실행은 실제 SDK의 DOM 삽입 방식과 타이밍에 의존한다.

추가 결함으로 확정하지 않는 조건: SDK가 새 루트를 다른 부모에 삽입하거나, DOM을 다시 교체하거나, 루트 삽입과 페인트 사이에 다른 작업을 수행하는 경우다. 현재 fixture가 해당 실제 동작을 입증하지 않는다.

필수 호스트 검증은 실제 Naver SDK에서 숨김 마커의 setIcon → 루트 교체 → aria-hidden 적용 순서를 관찰하고, 지도 이동·확대·release·unmount 이후 접근성 트리와 observer 정리를 확인하는 것이다.

새로운 최소 diff를 추가할 근거는 현재 없다. 따라서 REV-F-01 수정은 ACCEPT, 실제 SDK 일반화는 DEFER다.
