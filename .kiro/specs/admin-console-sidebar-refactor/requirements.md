# Requirements Document

## Introduction

관리자 운영 콘솔(`/admin`)의 사이드바에는 4개 섹션과 15개 메뉴 항목이 있습니다. 이 스펙은 각 메뉴가 "무엇을 위한 화면인지"를 명시적으로 정의하고, 관리자가 실제 업무를 끝까지 처리할 수 있는 수준으로 각 메뉴의 완성도를 올리며, 콘솔 전체에 하나의 시각 언어를 적용하는 것을 목표로 합니다.

### 확정된 범위 결정

- **완성도 목표**: 15개 메뉴 전부가 운영등급에 도달합니다. 설명 문구만 렌더링하고 데이터 연결이 없는 화면은 남기지 않습니다. 실험등급을 유지하는 메뉴는 없습니다.
- **정보 구조 변경**: 섹션 이름과 메뉴 배치를 조정할 수 있습니다. 모든 메뉴가 운영등급이 되면 `실험실` 섹션 이름은 실제 성격과 어긋나므로 재구성 대상입니다.
- **시각 언어 적용 범위**: 단색 계조 시각 언어를 데이터 시각화 표면뿐 아니라 **콘솔 셸 전체**에 적용합니다. 사이드바 섹션 배지 색, 활성 메뉴 강조, 모듈 머리말 제목, 버튼 톤을 모두 중립 계조로 통일하고, 색상은 오류·경고·성공 상태 표기에만 남깁니다.

### 현행 소스 관찰

현행 소스를 확인한 결과 다음 사항을 관찰했습니다. 요구사항은 이 관찰을 근거로 작성했습니다.

- 메뉴 정의가 최소 5곳에 분산되어 있습니다. `apps/web/lib/admin/admin-module-routing.ts`의 `ADMIN_CONSOLE_MODULE_IDS`, `apps/web/lib/admin/sidebar-order.ts`의 `ADMIN_SIDEBAR_ITEM_IDS`와 `DEFAULT_ADMIN_SIDEBAR_ORDER`, `AdminConsoleOverview.tsx`의 `consoleModules` 배열(12개 항목), 같은 파일의 `sidebarSections` 상수(`overview`, `routes`, `llm` 메타데이터를 별도로 하드코딩), 그리고 활성 메뉴 라벨을 다시 하드코딩하는 `activeModuleLabel` 삼항식입니다.
- `consoleModules`의 `description`, `actionLabel`, `href`, `priority` 필드는 값이 채워져 있으나 사이드바나 모듈 화면에서 읽히지 않습니다. `renderMenuItem`은 `item.title`과 `item.badge`만 렌더링합니다. 즉 각 메뉴의 목적 설명이 코드에는 있지만 관리자에게는 보이지 않습니다.
- 공통 머리말 컴포넌트 `AdminEmbeddedModuleShell`은 15개 중 5개 메뉴(`overview`, `routes`, `llm`, `audit`, `map-overlays`)에서만 사용됩니다. 나머지 10개는 `InlineModulePanel` 프레임 안에서 각자 다른 방식으로 렌더링됩니다.
- 지연 로딩 모듈 중 `banners`, `restaurant-refresh-history`, `users`, `storyboard`, `youtube-thumbnail-generator`, `insights`, `routes`는 `loading: () => null`입니다.
- `실험실` 섹션의 `llm`(운영 보조)은 3개 설명 카드와 운영 원칙 문단만 렌더링하며 데이터 조회가 없습니다.
- `audit`(감사 로그)를 렌더링하는 컴포넌트 이름은 `AuditPlaceholder`이지만 실제로 `/api/admin/audit-events`를 조회하고 로딩·빈·오류·세션만료 상태를 모두 갖고 있습니다. 이름과 실제 구현이 어긋나며, 배치 섹션(실험실)과 실제 성격(운영 감사)도 어긋납니다.
- 사이드바 대기 배지는 `submissions`와 `reviews`에만 존재합니다. 대기 건수 출처인 `/api/admin/pending-counts`는 `restaurant_submissions`, `restaurant_recommendation_requests`, `reviews` 3개 도메인 건수와 `total`, `readiness.status`를 반환합니다.
- 순서 설정 API는 `requireAdmin`, 동일 출처 검증, 4096바이트 본문 상한, 고정 한국어 오류 문구를 이미 적용합니다. 다만 본문이 상한을 넘어 `readBoundedJsonRequest`가 실패하면 본문을 `null`로 취급해 기본 순서를 저장하므로, 실패가 조용한 덮어쓰기로 이어집니다.
- `순서_정규화기`는 알 수 없는 섹션 이름을 버리고, `hasItemsOutsideCurrentSection`이 참이면 저장값 전체를 기본 순서로 되돌립니다. 따라서 섹션 이름 변경과 메뉴 재배치는 기존에 저장된 관리자별 순서를 전부 무효화합니다.
- 데이터 시각화는 색조로 계열을 구분합니다. `adminDashboardFocusPalette`는 `#14b8a6`, `#5eead4`, `#99f6e4`, `#38a5db`, `#94a3b8`, `#64748b`, `#f59e0b`, `#f43f5e`를 고정 16진수 리터럴로 보유하며, 트리맵 계열은 `#cbd5e1`, `#e2e8f0`을 추가로 사용합니다.
- 콘솔 셸도 색조에 의존합니다. `getSidebarBadgeClassName`은 섹션별로 앰버·스카이·바이올렛·에메랄드를 부여하고, 활성 메뉴는 `bg-primary`(라이트 `0 74% 42%`, 다크 `0 74% 50%`)를 사용하며, `AdminEmbeddedModuleShell`의 제목은 `bg-gradient-primary bg-clip-text text-transparent`, 아이콘은 `text-primary`입니다.
- 동작 축소는 Tailwind `motion-reduce:*` 유틸리티로 처리되고 있습니다. `framer-motion`은 의존성에 있으나 `apps/web/components/admin` 아래에서 사용되지 않습니다.

이 스펙의 범위는 사이드바 정보 구조, 메뉴 개념 정의, 메뉴별 완성도 기준선, 라우팅 정확성, 순서 개인화, 콘솔 시각 언어, 그리고 이들에 적용되는 저장소 규칙(관리자 인증, 고정 코드 응답, 위험 작업 절차, 개인정보 경계, 검증 증거)입니다. 각 메뉴가 담당하는 업무 자체를 새로 만드는 일은 범위 밖이며, 운영등급 달성에 필요한 데이터 연결과 상태 처리는 범위 안입니다.

### 시각 언어 참조 출처

시각 언어는 [Amicro Mono Charts 갤러리](https://amicro.vercel.app/mono-charts)를 **디자인 영감**으로만 참조합니다. 해당 라이브러리 패키지를 의존성에 추가하지 않고, 소스를 옮겨오지 않으며, 참조 사이트의 문구를 복제하지 않습니다. 구현은 이미 설치된 `recharts`, `framer-motion`, `tailwindcss`, `d3-hierarchy`, `d3-cloud`와 기존 CSS 변수 토큰만 사용합니다.

## Glossary

- **관리자_콘솔**: `/admin` 경로에서 동작하는 관리자 전용 화면 전체.
- **사이드바**: 관리자_콘솔에서 섹션과 메뉴 항목을 표시하고 활성 메뉴를 전환하는 탐색 영역. 데스크톱 세로 목록과 모바일 드롭다운을 모두 포함한다.
- **섹션**: 사이드바에서 메뉴 항목을 구분하는 상위 단위. 4개를 유지하며 이름과 소속 메뉴는 이 스펙에서 재정의한다.
- **메뉴_항목**: 사이드바에서 선택 가능한 하나의 작업 화면 진입점. 15개.
- **메뉴_레지스트리**: 메뉴_항목과 섹션의 정의를 보관하는 단일 원천. 메뉴 ID, 표시 제목, 목적 문장, 담당 업무, 1차 데이터 출처, 대표 작업 이름, 산출물_성격을 보관한다.
- **메뉴_라우터**: 주소 질의 문자열과 활성 메뉴_항목 사이를 변환하고 정규_링크를 생성하는 구성 요소.
- **정규_링크**: 메뉴_항목을 가리키는 표준 주소. 대시보드 (KPI)는 `/admin`, 그 외 메뉴는 `/admin?module={메뉴 ID}`.
- **모듈_셸**: 활성 메뉴_항목의 머리말(제목, 요약 문장, 대표 작업 영역)과 본문 경계를 제공하는 공통 컴포넌트.
- **모듈_패널**: 하나의 메뉴_항목이 담당하는 실제 작업 화면.
- **모듈_그리드**: 15개 메뉴_항목을 카드 형태로 나열하고 검색과 섹션 필터를 제공하는 탐색 표면.
- **완성도_기준선**: 모든 메뉴_항목이 충족해야 하는 최소 상태 집합. 머리말, 로딩 상태, 빈 상태, 오류 상태, 권한 상태, 대표 작업.
- **운영등급**: 관리자가 담당 업무를 해당 화면에서 완결할 수 있는 상태. 1차 데이터 출처에 연결되어 있고 완성도_기준선을 충족하며 대표 작업이 동작한다. 이 스펙에서 15개 메뉴_항목 전부의 목표 상태다.
- **산출물_성격**: 메뉴_항목이 관리자에게 제시하는 결과의 종류. 조회, 변경, 모델생성 중 하나.
- **모델생성_산출물**: 생성 모델이 만든 결과물. 사실이 아닌 초안 또는 제안으로 표기해야 한다.
- **순서_설정_API**: `/api/admin/preferences/sidebar-order`의 조회 및 저장 처리기.
- **순서_정규화기**: 저장된 순서 값을 알려진 섹션과 메뉴 ID만 남긴 정규 형태로 변환하는 함수.
- **대기_배지**: 메뉴_항목에 표시되는 미처리 건수 표식.
- **콘솔_시각_체계**: 관리자_콘솔의 색, 계조, 모서리 반경, 경계선, 글꼴 크기 규칙을 정의하는 토큰 집합과 그 사용 규칙.
- **중립_계조**: 색조 정보를 계열 구분에 사용하지 않고 명도와 불투명도 단계만으로 구성한 표현 값의 순서 있는 집합으로, 단계 수는 정확히 6단계다. `--foreground`, `--muted-foreground`, `--muted`, `--border`, `--card`, `--background` 토큰과 불투명도 단계에서 파생한다.
- **상태_색상**: 오류, 경고, 성공 3개 상태 역할에만 사용하는 색상 토큰 집합.
- **데이터_시각화**: 관리자_콘솔에서 수치를 도형으로 표현하는 표면. 스파크라인, 게이지 호, 방사형 막대, 활동 히트맵, 단계 퍼널, 불릿 바, 워터폴, 트리맵, 계조 누적 막대, 범위 밴드 영역을 포함한다.
- **카드_메타_행**: 데이터_시각화 카드 하단에 왼쪽 설명 문자열과 오른쪽 강조 값을 고정폭 글꼴로 표시하는 한 줄 영역.
- **관리자_API**: 메뉴_항목이 사용하는 `/api/admin/*` 경로 처리기.
- **감사_기록기**: 관리자 작업의 의도와 결과를 추가 전용으로 기록하는 구성 요소.
- **개인정보_경계**: `apps/web/lib/privacy/sanitize.ts`가 제공하는 단정 및 마스킹 경로.
- **위험_작업_절차**: 미리보기 → 확인 → 적용 → 재확인 → 감사 기록 5단계.
- **검증_스위트**: `apps/web/tests-unit`의 단위·소스 계약 시험과 `apps/web/tests`의 브라우저 시험 모음.

## 메뉴 개념 정의 기준표

아래 표는 요구사항 1이 요구하는 메뉴_레지스트리의 초기 내용이며, 섹션 열은 요구사항 5가 요구하는 재구성 결과입니다. 15개 메뉴_항목 전부의 목표 상태는 운영등급입니다.

| 메뉴 ID | 표시 제목 | 섹션 | 목적 | 담당 운영 업무 | 1차 데이터 출처 | 산출물_성격 |
| --- | --- | --- | --- | --- | --- | --- |
| `overview` | 대시보드 (KPI) | 판단 | 채널 성과와 미처리 업무량을 한 화면에서 파악한다 | 오늘 우선 처리할 업무 판단 | `/api/admin/pending-counts`, `/api/admin/youtube-kpis` | 조회 |
| `insights` | 핵심 인사이트 | 판단 | 콘텐츠 성과 변화를 해석한다 | 조회수·좋아요·댓글·영상 길이 추이 확인 | `/api/admin/youtube-kpis`, `/api/admin/youtube-kpi-collection-logs` | 조회 |
| `llm` | 운영 보조 | 판단 | 위험 작업 전 현재 대기·실패·위험 후보를 읽기 전용으로 요약한다 | 다음 검수 후보 확인, 위험 작업 점검표 확인 | `/api/admin/pending-counts`, `/api/admin/system-status`, `/api/admin/audit-events` | 모델생성 |

| `submissions` | 제보 관리 | 검수 | 사용자 신규·수정 제보를 판정한다 | 제보 승인, 반려, 반영 | `/api/admin/restaurant-requests` | 변경 |
| `reviews` | 리뷰 관리 | 검수 | 미승인 리뷰와 증빙을 판정한다 | 리뷰 승인, 중복·삭제 후보 처리 | `/api/admin/ocr-receipts`, 리뷰 조회 경로 | 변경 |
| `map-overlays` | 지도 오버레이 | 운영 | 공개 지도에 노출되는 오버레이를 통제한다 | 수동 오버레이 편집, 트렌드 제안 판정, 실행 상태 확인 | `/api/admin/map-overlays`, `/api/admin/trend-proposals`, `/api/admin/trend-job-requests` | 변경 |

| `pipeline` | 크롤러 파이프라인 | 운영 | 수집 파이프라인의 실행 상태를 관측하고 대상별 실행을 요청한다 | 실행 요청, 실패 확인, 재실행 판단 | `/api/admin/pipeline` | 변경 |
| `audit` | 감사 로그 | 운영 | 관리자 작업의 부분 감사 기록을 조회한다 | 사용자 관리 감사 추적, 개인정보 사고 대응 진입 | `/api/admin/audit-events` | 조회 |
| `storyboard` | 스토리보드 생성 | 콘텐츠 제작 | 다음 영상 소재와 씬별 촬영안 초안을 만든다 | 히트맵 기반 소재 도출, 씬 초안 생성·검토 | `/api/admin/storyboard` | 모델생성 |
| `youtube-thumbnail-generator` | 유튜브 썸네일 생성 | 콘텐츠 제작 | 업로드용 16:9 썸네일 초안을 만든다 | 주제·참고 이미지 입력, 초안 생성, 텍스트 편집 | `/api/admin/youtube-thumbnail-generator`, `/api/admin/image-generation-readiness` | 모델생성 |

섹션 재구성 근거:

- **판단**(3개): 무엇을 먼저 처리할지 결정하는 읽기 전용 화면. 기존 `홈`을 확장했습니다.
- **검수**(4개): 데이터 정확성 판정. 기존과 동일합니다.
- **운영**(6개): 공개 노출, 권한, 수집 실행, 감사 기록 통제. `routes`와 `audit`을 기존 `실험실`에서 이동했습니다.
- **콘텐츠 제작**(2개): 채널 업로드용 산출물 생성. 기존 `실험실`을 대체합니다.

`llm`, `storyboard`, `youtube-thumbnail-generator`는 운영등급이면서 산출물_성격이 모델생성입니다. 운영등급은 화면의 완성도를 뜻하고, 모델생성 표기는 산출물의 신뢰 수준을 뜻하며 두 개념은 별개입니다.

## Requirements

### 요구사항 1: 메뉴 개념 정의를 단일 원천으로 확보

**사용자 스토리:** 관리자 콘솔 운영자로서, 사이드바 각 메뉴가 어떤 목적과 담당 업무를 갖는지 한곳에 정의되어 있기를 원한다. 그래야 어떤 화면에서 무엇을 처리해야 하는지 판단할 수 있다.

#### 수용 기준

1. THE 메뉴_레지스트리 SHALL 15개 메뉴_항목 각각을 정확히 1회 선언하고, 각 선언에 메뉴 ID, 표시 제목, 목적 문장, 담당 운영 업무, 1차 데이터 출처, 대표 작업 이름, 산출물_성격 7개 필드를 모두 제공한다.
2. THE 메뉴_레지스트리 SHALL 4개 섹션 각각에 대해 서로 다른 섹션 이름 1개와 섹션 목적 문장 1개를 제공하며, 섹션 이름은 8자 이내, 섹션 목적 문장은 60자 이내로 제공한다.
3. THE 메뉴_레지스트리 SHALL 표시 제목, 목적 문장, 담당 운영 업무, 대표 작업 이름을 각각 한글 문자를 1자 이상 포함하는 문자열로 제공하며, 표시 제목은 14자 이내, 목적 문장과 담당 운영 업무는 각각 60자 이내, 대표 작업 이름은 20자 이내로 제공한다.
4. WHEN 사이드바가 메뉴_항목을 렌더링할 때, THE 사이드바 SHALL 데스크톱 세로 목록과 모바일 드롭다운 양쪽에서 해당 메뉴 ID에 대응하는 메뉴_레지스트리의 표시 제목 문자열을 변형 없이 표시한다.
5. WHEN 메뉴_항목이 키보드 초점 또는 마우스 진입을 받을 때, THE 사이드바 SHALL 120밀리초 이내에 해당 메뉴_항목의 목적 문장을 그 메뉴_항목에 `aria-describedby`로 연결된 안내 영역에 표시한다.
6. WHEN 모듈_셸이 머리말을 렌더링할 때, THE 모듈_셸 SHALL 활성 메뉴_항목의 표시 제목을 머리말 제목으로, 목적 문장을 머리말 요약 문장으로 사용한다.
7. IF 메뉴_레지스트리의 어떤 필드가 누락되었거나 빈 문자열 또는 공백 문자만으로 구성되었으면, THEN THE 검증_스위트 SHALL 해당 메뉴_항목의 메뉴 ID와 필드 이름을 포함한 실패를 보고한다.
8. IF 메뉴_레지스트리의 메뉴_항목 수가 15가 아니거나 동일한 메뉴 ID가 2회 이상 나타나면, THEN THE 검증_스위트 SHALL 실패를 보고한다.
9. THE 메뉴_레지스트리 SHALL 각 메뉴_항목의 산출물_성격을 조회, 변경, 모델생성 중 정확히 1개 값으로 제공한다.
10. THE 메뉴_레지스트리 SHALL 각 메뉴_항목의 1차 데이터 출처를 1개 이상 3개 이하의 출처 이름 목록으로 제공한다.

### 요구사항 2: 메뉴 정의 중복 제거와 파생 일관성

**사용자 스토리:** 관리자 콘솔 개발자로서, 메뉴를 한 곳에만 등록하면 사이드바·라우팅·머리말·순서 저장에 모두 반영되기를 원한다. 그래야 정의가 서로 어긋나 화면과 주소가 불일치하는 상황을 막을 수 있다.

#### 수용 기준

1. THE 관리자_콘솔 SHALL 라우팅 가능한 메뉴 ID 집합과 사이드바 배치 대상 메뉴 ID 집합을 메뉴_레지스트리에서만 파생하여, 두 집합이 순서와 무관하게 동일한 15개 메뉴 ID로 구성되도록 유지한다.
2. WHEN 관리자_콘솔이 활성 메뉴_항목의 브라우저 제목 라벨을 계산할 때, THE 관리자_콘솔 SHALL 활성 메뉴 ID로 메뉴_레지스트리를 조회한 표시 제목을 사용한다.
3. WHEN 관리자_콘솔이 지연 로딩 대상 모듈_패널을 결정할 때, THE 관리자_콘솔 SHALL 메뉴 ID를 키로 갖는 대응에서 활성 메뉴 ID에 대응하는 모듈_패널 1개만 선택한다.
4. FOR ALL 메뉴_레지스트리에 등록된 메뉴_항목, 사이드바 표시 대상, 정규_링크 생성 대상, 모듈_셸 머리말 대상, 모듈_그리드 카드 대상, 순서_정규화기 허용 메뉴 ID 집합 SHALL 해당 메뉴_항목의 메뉴 ID를 각각 정확히 1회 포함한다.
5. WHERE 표시 제목, 목적 문장, 대표 작업 이름, 섹션 이름 중 하나가 사이드바, 모듈_셸, 모듈_그리드, 브라우저 제목 중 두 개 이상에서 표시되는 경우, THE 관리자_콘솔 SHALL 각 표시 지점에서 동일한 메뉴 ID로 메뉴_레지스트리를 조회한 값을 사용한다.
6. THE 메뉴_레지스트리 SHALL 사이드바, 모듈_셸, 모듈_그리드, 브라우저 제목, 순서_정규화기 허용 목록 중 최소 1곳에서 읽히는 필드만 보유한다.
7. THE 검증_스위트 SHALL 라우팅 메뉴 ID 집합과 사이드바 메뉴 ID 집합이 각각 15개 원소를 갖고 순서와 무관하게 동일함을 단정한다.
8. THE 검증_스위트 SHALL 메뉴_레지스트리의 메뉴 필드 7개와 섹션 필드 2개 각각이 사이드바, 모듈_셸, 모듈_그리드, 브라우저 제목, 순서_정규화기 허용 목록 중 최소 1곳에서 읽히는지를 단정한다.
9. IF 사이드바, 모듈_셸, 모듈_그리드, 브라우저 제목 중 어느 표시 지점이 메뉴_레지스트리 조회 없이 표시 제목 문자열 또는 섹션 이름 문자열을 직접 선언하면, THEN THE 검증_스위트 SHALL 해당 표시 지점을 실패로 보고한다.
10. THE 검증_스위트 SHALL 메뉴 ID를 키로 갖는 대응에서 메뉴_레지스트리 메뉴 ID 1개 누락과 메뉴_레지스트리에 없는 키 1개 추가를 각각 실패로 보고한다.
11. IF 활성 메뉴 ID에 대응하는 모듈_패널 항목이 없으면, THEN THE 관리자_콘솔 SHALL 고정 한국어 오류 문구를 표시하고 사이드바의 메뉴_항목 선택 기능을 유지한다.

### 요구사항 3: 모든 메뉴의 공통 완성도 기준선

**사용자 스토리:** 관리자로서, 어떤 메뉴로 들어가도 제목과 요약, 진행 상태, 빈 상태, 오류 상태를 같은 방식으로 확인하기를 원한다. 그래야 화면마다 다른 규칙을 익히지 않고 업무를 처리할 수 있다.

#### 수용 기준

1. WHEN 메뉴_항목이 활성화될 때, THE 모듈_셸 SHALL 메뉴_레지스트리의 표시 제목 1개, 목적 문장 1개, 대표 작업 제어 영역 1개를 포함한 머리말을 렌더링한다.
2. WHEN 모듈_셸이 머리말을 렌더링할 때, THE 모듈_셸 SHALL 작업 영역의 `aria-labelledby` 값을 머리말 표시 제목 요소의 식별자와 일치시킨다.
3. WHILE 메뉴_항목의 1차 데이터 요청이 시작된 시점부터 응답 처리 또는 실패 처리가 끝나는 시점까지, THE 모듈_패널 SHALL 완료 화면과 같은 수의 주요 영역 자리표시자를 가진 해당 메뉴 전용 골격 화면을 표시한다.
4. WHILE 메뉴_항목의 코드 번들 적재가 진행 중인 동안, THE 관리자_콘솔 SHALL 빈 렌더링 결과 대신 해당 메뉴 전용 골격 화면을 표시한다.
5. WHEN 메뉴_항목의 1차 데이터 요청이 성공하고 결과 건수가 0일 때, THE 모듈_패널 SHALL 한국어 빈 상태 안내 문장 1개와 다음 조치 문장 1개를 표시한다.
6. IF 메뉴_항목의 1차 데이터 요청이 실패하면, THEN THE 모듈_패널 SHALL 원인 진단 정보를 제외한 고정 한국어 오류 문장 1개와 다시 시도 제어 1개를 표시한다.
7. IF 관리자 세션 확인 실패로 메뉴_항목의 1차 데이터 요청이 거부되면, THEN THE 모듈_패널 SHALL 고정 한국어 안내 문장 1개와 활성 메뉴_항목의 정규_링크로 복귀하는 재로그인 제어 1개를 표시한다.
8. WHEN 활성 메뉴_항목이 변경될 때, THE 관리자_콘솔 SHALL aria-live 영역의 내용을 전환된 메뉴_항목의 표시 제목 1개로 교체하고 같은 전환에 대해 추가 알림 문자열을 생성하지 않는다.
9. THE 모듈_패널 SHALL 15개 메뉴_항목 전부에 대해 로딩 상태, 빈 상태, 오류 상태를 서로 다른 고정 데이터 속성 값으로 표시한다.
10. THE 모듈_셸 SHALL 15개 메뉴_항목 전부에서 동일한 머리말 구성 요소를 사용하고 머리말 렌더링을 생략하는 설정을 제공하지 않는다.
11. FOR ALL 15개 메뉴_항목, 임의 시점에 모듈_패널이 동시에 표시하는 로딩 상태 표식, 빈 상태 표식, 오류 상태 표식의 수 SHALL 1 이하이다.
12. WHEN 관리자가 다시 시도 제어를 실행할 때, THE 모듈_패널 SHALL 실패한 1차 데이터 요청과 같은 대상 및 같은 질의 조건으로 요청을 재발행한다.
13. WHEN 골격 화면이 1차 데이터 결과 화면 또는 빈 상태 화면으로 교체될 때, THE 모듈_패널 SHALL 머리말 하단 기준선의 세로 위치 변화를 4픽셀 이내로 유지한다.

### 요구사항 4: 15개 메뉴 전부의 운영등급 달성

**사용자 스토리:** 관리자로서, 사이드바의 어떤 메뉴를 열어도 실제 데이터로 업무를 처리할 수 있기를 원한다. 그래야 설명만 있는 화면을 열고 다른 경로를 다시 찾는 일이 없어진다.

#### 수용 기준

1. THE 메뉴_레지스트리 SHALL 15개 메뉴_항목 전부를 운영등급으로 분류하며 운영등급 이외의 완성도 값을 제공하지 않는다.
2. WHEN 메뉴_항목이 활성화될 때, THE 모듈_패널 SHALL 메뉴_레지스트리에 명시된 1차 데이터 출처 전부에 대해 조회를 발신하고, 활성화 시점부터 10초 이내에 조회 결과, 빈 상태, 오류 상태 중 정확히 하나를 표시한다.
3. WHEN 메뉴_항목이 활성화될 때, THE 모듈_패널 SHALL 메뉴_레지스트리에 명시된 대표 작업 제어를 조회 결과, 빈 상태, 오류 상태 전부에서 360픽셀 폭 표시 영역과 1280픽셀 폭 표시 영역의 최초 표시 화면 안에 세로 스크롤 없이 도달 가능한 위치로 제공한다.
4. WHERE 메뉴_항목의 산출물_성격이 모델생성인 경우, THE 모듈_패널 SHALL 표시되는 모델생성_산출물 항목마다 초안 또는 제안 표기를 해당 항목과 같은 화면 영역에 표시한다.
5. WHERE 메뉴_항목의 산출물_성격이 모델생성인 경우, THE 모듈_패널 SHALL 표시되는 모델생성_산출물 항목마다 근거로 사용한 1차 데이터 출처 이름 전부를 표시한다.
6. WHERE 메뉴_항목의 산출물_성격이 모델생성이고 해당 모델생성_산출물이 데이터 변경을 제안하는 경우, THE 모듈_패널 SHALL 변경 적용을 담당 메뉴_항목의 위험_작업_절차로 위임하고 위임 대상 메뉴_항목의 표시 제목을 표시한다.
7. THE 관리자_콘솔 SHALL 15개 메뉴_항목 각각의 산출물_성격을 조회, 변경, 모델생성 중 정확히 하나의 값으로 활성 작업 영역에 구분 가능한 데이터 속성으로 표시한다.
8. IF 메뉴_항목의 모듈_패널이 1차 데이터 출처 조회 발신 없이 고정 설명 문구만 렌더링하면, THEN THE 검증_스위트 SHALL 해당 메뉴_항목을 메뉴 ID와 함께 실패로 보고한다.
9. THE 검증_스위트 SHALL 15개 메뉴_항목 각각의 산출물_성격 표식과 메뉴_레지스트리 값의 일치를 단정한다.
10. WHERE 메뉴_항목의 산출물_성격이 모델생성인 경우, THE 모듈_패널 SHALL 모델생성_산출물을 저장된 데이터에 직접 반영하는 제어를 제공하지 않는다.
11. IF 모델생성_산출물의 생성 준비 상태가 사용 불가로 보고되면, THEN THE 모듈_패널 SHALL 이미 표시된 1차 데이터 조회 결과를 유지한 채 생성 제어를 비활성 상태로 표시하고 고정 한국어 안내 문구를 표시한다.
12. THE 검증_스위트 SHALL 15개 메뉴_항목 각각의 1차 데이터 출처 조회 발신 경로 존재, 로딩 상태·빈 상태·오류 상태 표식 존재, 대표 작업 제어 존재, 그리고 산출물_성격이 모델생성인 메뉴_항목에 위험_작업_절차를 거치지 않는 데이터 변경 경로가 없음을 단정한다.

### 요구사항 5: 섹션 정보 구조 재구성과 저장된 순서 이관

**사용자 스토리:** 관리자로서, 섹션 이름이 실제 업무 성격과 맞기를 원한다. 그래야 새 담당자도 메뉴 위치를 추측으로 찾지 않는다.

#### 수용 기준

1. THE 메뉴_레지스트리 SHALL 섹션 수를 정확히 4로 고정하고 판단, 검수, 운영, 콘텐츠 제작 4개 이름만을 이 순서로 제공한다.
2. THE 메뉴_레지스트리 SHALL 15개 메뉴_항목 각각을 정확히 1개 섹션에 배치하여 판단 3개, 검수 4개, 운영 6개, 콘텐츠 제작 2개 구성을 제공한다.
3. THE 메뉴_레지스트리 SHALL 감사 로그 메뉴_항목 `audit`을 운영 섹션에 배치하고 콘텐츠 제작 섹션에는 배치하지 않는다.
4. THE 메뉴_레지스트리 SHALL 4개 섹션 이름과 15개 메뉴_항목 각각의 섹션 값을 메뉴 개념 정의 기준표의 섹션 열 값과 동일하게 제공한다.
5. IF 저장된 순서 값의 섹션 목록 또는 섹션별 항목 키에 메뉴_레지스트리의 폐지된 섹션 이름 목록에 있는 이름이 1개 이상 포함되면, THEN THE 순서_정규화기 SHALL 부분 보존 없이 4개 섹션과 15개 메뉴 ID를 각각 정확히 1회 포함한 새 기본 순서를 반환한다.
6. IF 저장된 순서 값이 어떤 섹션 키 아래에 그 섹션의 새 기본 배치에 속하지 않는 메뉴 ID를 1개 이상 포함하면, THEN THE 순서_정규화기 SHALL 해당 메뉴 ID만 제거하는 대신 새 기본 순서 전체를 반환한다.
7. WHEN 사이드바가 순서_정규화기의 되돌림 결과를 관리자_콘솔 적재 이후 처음 수신할 때, THE 사이드바 SHALL 메뉴 구성 변경으로 순서가 초기화되었음을 알리는 고정 한국어 문구 1개를 1회 표시한다.
8. THE 검증_스위트 SHALL 폐지된 섹션 이름 홈 또는 실험실을 포함한 저장값 입력에 대해 순서_정규화기 결과가 새 기본 순서와 같음을 단정한다.
9. THE 메뉴_레지스트리 SHALL 폐지된 섹션 이름 목록으로 홈과 실험실 2개를 보유한다.
10. IF 되돌림 결과가 같은 관리자_콘솔 적재 안에서 다시 수신되면, THEN THE 사이드바 SHALL 순서 초기화 안내 문구를 다시 표시하지 않는다.
11. THE 검증_스위트 SHALL 이동한 메뉴 ID `insights`, `llm`, `routes`, `audit`을 이전 섹션 키 아래에 담은 저장값 입력에 대해 순서_정규화기 결과가 새 기본 순서와 같음을 단정한다.

### 요구사항 6: 메뉴 라우팅과 활성 상태 정확성

**사용자 스토리:** 관리자로서, 주소를 공유하거나 뒤로 가기를 눌러도 같은 메뉴 화면에 도달하기를 원한다. 그래야 다른 담당자에게 작업 화면을 그대로 전달할 수 있다.

#### 수용 기준

1. WHEN 관리자가 사이드바에서 현재 활성 상태가 아닌 메뉴_항목을 선택할 때, THE 메뉴_라우터 SHALL 해당 항목의 정규_링크로 주소를 갱신하고 브라우저 이력 항목 1개를 추가한다.
2. WHERE 선택된 메뉴_항목이 대시보드 (KPI)인 경우, THE 메뉴_라우터 SHALL `module` 질의 이름을 포함하지 않는 `/admin`을 정규_링크로 사용하고, 나머지 14개 메뉴_항목에는 `/admin?module={메뉴 ID}` 형식을 사용한다.
3. WHEN 주소에 `view` 또는 `tab` 질의가 포함된 기존 링크로 진입할 때, THE 메뉴_라우터 SHALL 해당 조합이 가리키는 검수 메뉴_항목 1개를 활성화하고, `view`와 `tab` 질의를 제거한 정규_링크로 주소를 치환하며 고정 한국어 안내 문구를 표시한다.
4. IF 주소의 `module` 값이 메뉴_레지스트리에 없고 `view` 또는 `tab` 질의로 해석되는 메뉴_항목도 없으면, THEN THE 메뉴_라우터 SHALL 대시보드 (KPI)를 활성화하고 고정 한국어 안내 문구를 표시하며, 해석되지 않은 `module` 값을 치환된 주소, 안내 문구, 브라우저 제목 어디에도 포함하지 않는다.
5. WHEN 메뉴_라우터가 정규_링크를 생성할 때, THE 메뉴_라우터 SHALL 질의 이름을 `module`, `video_id`, `issue`, `reason` 4개로 한정하고, 진입 주소의 `video_id`, `issue`, `reason` 값 중 빈 문자열이 아닌 값을 원래 문자열 그대로 유지한다.
6. WHEN 메뉴_항목이 활성화될 때, THE 사이드바 SHALL 데스크톱 목록과 모바일 드롭다운 각각에서 활성 메뉴_항목에만 `aria-current="page"`를 부여하고 나머지 14개 메뉴_항목에는 부여하지 않는다.
7. WHEN 메뉴_항목이 활성화될 때, THE 관리자_콘솔 SHALL 브라우저 제목에 활성 메뉴_항목의 표시 제목과 관리자 콘솔 문자열을 포함하고, 다른 14개 메뉴_항목의 표시 제목은 포함하지 않는다.
8. WHEN 관리자가 브라우저 뒤로 가기 또는 앞으로 가기를 사용할 때, THE 관리자_콘솔 SHALL 이동한 주소가 가리키는 메뉴 ID와 활성 메뉴_항목을 일치시키고 새 이력 항목을 추가하지 않는다.
9. FOR ALL 15개 메뉴_항목과 `video_id`, `issue`, `reason` 질의 값 조합, 정규_링크 생성 후 해당 주소에서 다시 해석한 메뉴 ID와 보존 대상 질의 값 SHALL 원래 메뉴 ID와 원래 질의 값과 같다.
10. WHEN 관리자가 정규_링크와 다른 `/admin` 주소로 진입할 때, THE 메뉴_라우터 SHALL 새 이력 항목을 추가하지 않고 현재 이력 항목을 정규_링크로 교체한다.
11. FOR ALL `/admin` 주소의 질의 조합, 메뉴_라우터가 생성한 정규_링크에 정규_링크 생성을 한 번 더 적용한 결과 SHALL 최초 생성 결과와 같다.
12. IF 관리자가 이미 활성 상태인 메뉴_항목을 선택하면, THEN THE 메뉴_라우터 SHALL 현재 주소를 유지하고 새 이력 항목을 추가하지 않는다.

### 요구사항 7: 관리자 계정별 사이드바 순서 개인화

**사용자 스토리:** 관리자로서, 자주 쓰는 메뉴를 위로 올린 순서가 다음 접속에도 유지되기를 원한다. 그래야 매번 같은 메뉴를 찾는 시간을 줄일 수 있다.

#### 수용 기준

1. WHEN 사이드바가 처음 렌더링될 때, THE 순서_설정_API SHALL 요청 관리자 계정에 저장된 값에 순서_정규화기를 적용한 순서를 반환하고, 저장된 값이 없으면 기본 순서를 반환한다.
2. IF 저장된 순서 조회가 실패하면, THEN THE 사이드바 SHALL 기본 순서를 표시하고, 저장 요청을 전송하지 않으며, 고정 한국어 안내 문구 1건을 표시한다.
3. WHILE 순서 편집이 잠긴 상태인 동안, THE 사이드바 SHALL 항목 이동 제어, 섹션 이동 제어, 초기화 제어를 비활성 상태로 유지하고 저장 요청을 전송하지 않는다.
4. WHILE 순서 편집이 켜진 상태인 동안, WHEN 관리자가 메뉴_항목 또는 섹션을 1회 이동할 때, THE 순서_설정_API SHALL 그 이동 1회에 대응하는 저장 요청 1건만 처리하여 정규화된 순서를 요청 관리자 계정에 저장하고 저장된 값을 응답 본문으로 반환한다.
5. WHEN 순서_설정_API가 저장된 값을 응답할 때, THE 사이드바 SHALL 응답 본문의 순서 값으로 화면 순서를 교체하고 고정 한국어 성공 문구 1건을 표시한다.
6. IF 저장 요청이 실패 응답 또는 요청 오류로 끝나면, THEN THE 사이드바 SHALL 이동 조작이 반영된 임시 순서를 화면에 유지하고, 자동 재시도 요청을 전송하지 않으며, 저장되지 않았음을 알리는 고정 한국어 문구 1건을 표시한다.
7. WHILE 순서 편집이 켜진 상태인 동안, WHEN 관리자가 초기화를 실행할 때, THE 순서_설정_API SHALL 기본 순서를 저장하고 기본 순서를 응답 본문으로 반환한다.
8. THE 순서_정규화기 SHALL 알 수 없는 섹션 이름, 알 수 없는 메뉴 ID, 중복 메뉴 ID, 배열이 아닌 섹션 목록 값, 배열이 아닌 메뉴 목록 값을 제외한 결과를 반환하고, 기본 배치와 다른 섹션에 놓인 메뉴 ID가 1개 이상이면 기본 순서 전체를 반환한다.
9. THE 순서_정규화기 SHALL 정규화 결과가 4개 섹션 전부와 15개 메뉴 ID를 각각 정확히 1회 포함하도록 반환한다.
10. FOR ALL 입력 값(객체가 아닌 값, 빈 객체, 알 수 없는 섹션 이름, 알 수 없는 메뉴 ID, 중복 메뉴 ID, 섹션 간 교차 배치를 포함하여 검증_스위트가 생성한 100개 이상), 순서_정규화기를 1회 적용한 결과와 2회 적용한 결과 SHALL 같다.
11. FOR ALL 정규화된 순서 값(검증_스위트가 생성한 100개 이상), 동일 관리자 계정에서 두 요청 사이에 다른 저장 요청이 없을 때 저장 후 조회한 결과 SHALL 저장 요청의 정규화된 값과 같다.
12. IF 저장 요청 본문이 4096바이트를 초과하면(선언된 본문 길이 기준 또는 실제 수신 바이트 기준), THEN THE 순서_설정_API SHALL 저장을 생략하고, 기존 저장 값을 변경하지 않으며, 고정 코드 응답을 반환한다.
13. IF 저장 요청이 동일 출처 검증을 통과하지 못하면, THEN THE 순서_설정_API SHALL 본문을 읽지 않고 저장을 생략하며 HTTP 403과 고정 문구를 반환한다.
14. WHERE 요청 관리자 식별자가 저장 가능한 형식이 아닌 경우, THE 순서_설정_API SHALL 저장소 읽기와 쓰기를 수행하지 않고, 요청에 담긴 순서 값을 정규화한 결과를 반환하며, 요청에 순서 값이 없으면 기본 순서를 반환한다.
15. WHILE 저장 요청의 응답이 확정되지 않은 동안, THE 사이드바 SHALL 항목 이동 제어, 섹션 이동 제어, 초기화 제어를 비활성 상태로 유지하고, 진행 중인 저장 요청이 1건을 넘지 않도록 새 저장 요청을 전송하지 않는다.
16. IF 저장 요청 본문을 순서 값이 담긴 JSON 객체로 읽지 못하면(요청 매체 유형이 JSON이 아님, JSON 형식 오류, 선언된 본문 길이와 실제 수신 바이트 불일치, 본문 수신이 1초 안에 끝나지 않음, 본문에 순서 값이 없음, 순서 값이 객체가 아님 포함), THEN THE 순서_설정_API SHALL 저장을 생략하고, 기존 저장 값을 그대로 유지하며, 고정 코드 응답을 반환한다.
17. WHEN 동일 관리자 계정의 저장 요청 2건이 겹쳐 처리될 때, THE 순서_설정_API SHALL 두 요청의 값을 병합하지 않고 나중에 저장이 완료된 요청의 정규화된 값을 최종 저장 값으로 유지하며, 각 응답 본문에 해당 요청이 기록한 값을 반환한다.

### 요구사항 8: 사이드바 대기 상태 표시

**사용자 스토리:** 관리자로서, 사이드바만 보고 지금 처리해야 할 업무가 있는 메뉴를 알아보기를 원한다. 그래야 각 메뉴를 하나씩 열어 확인하지 않아도 된다.

#### 수용 기준

1. WHERE 메뉴_레지스트리가 해당 메뉴_항목에 대해 1개 이상의 대기 건수 도메인을 선언한 경우에만, THE 사이드바 SHALL 해당 메뉴_항목에 대기_배지를 표시하고, 도메인을 선언하지 않은 나머지 13개 메뉴_항목에는 대기_배지를 표시하지 않는다. 대기 건수 도메인을 선언하는 메뉴_항목은 제보 관리와 리뷰 관리 정확히 2개다.
2. WHEN 대기 건수가 1 이상 99 이하일 때, THE 사이드바 SHALL 대기_배지에 해당 정수를 그대로 표시하고, 대기 건수가 100 이상일 때 `99+`로 축약 표시하며, 대기 건수는 오류/경고/성공 상태가 아니므로 대기_배지에 상태_색상 토큰을 사용하지 않는다.
3. WHEN 대기 건수가 0일 때, THE 사이드바 SHALL 대기_배지에 기본 표식 스타일을 적용하고, 상태_색상 토큰을 사용하지 않는다.
4. IF 대기 건수 조회가 실패하면, THEN THE 사이드바 SHALL 대기_배지를 생략하고, 이전에 성공한 대기 건수를 다시 표시하지 않으며, 모든 메뉴_항목의 선택 기능을 계속 동작 가능한 상태로 유지한다.
5. WHILE 사이드바가 접힌 상태인 동안, THE 사이드바 SHALL 대기 건수가 1 이상인 메뉴_항목의 대기_배지를 점 표식으로 축약하고, 대기 건수가 0인 메뉴_항목에는 점 표식을 표시하지 않는다.
6. THE 사이드바 SHALL 메뉴_항목 접근성 라벨에 대기_배지가 축약 표시(`99+`) 중인 경우에도 축약하지 않은 정수 대기 건수와 그 의미를 포함한다.
7. THE 메뉴_레지스트리 SHALL 대기_배지를 갖는 2개 메뉴_항목과 각 대기 건수 출처 도메인을 명시한다. 제보 관리는 `restaurant_submissions`와 `restaurant_recommendation_requests` 2개 도메인을, 리뷰 관리는 `reviews` 1개 도메인을 출처로 갖는다.
8. WHERE 대기 건수 출처의 준비 상태가 저하로 보고되는 경우, THE 사이드바 SHALL 대기_배지에 부분 집계 표식을 표시한다.
9. FOR ALL 대기_배지를 갖는 메뉴_항목에 대해, THE 사이드바 SHALL 표시 대기 건수를 메뉴_레지스트리가 해당 메뉴_항목에 선언한 모든 도메인 건수의 합으로 산출하고, 그 값을 0 이상의 정수로 표시한다.
10. WHILE 관리자가 사이드바가 포함된 화면에 머무는 동안, THE 사이드바 SHALL 60초 이하 간격으로 관리자_API를 통해 대기 건수를 재조회한다.
11. IF 대기 건수 집계 시각이 현재 시각보다 180초 이상 이전이면, THEN THE 사이드바 SHALL 대기_배지에 지연 집계 표식을 표시하고 마지막으로 성공한 대기 건수 값을 유지한다.

### 요구사항 9: 단색 계조 시각 언어를 콘솔 전체에 적용

**사용자 스토리:** 관리자로서, 색이 의미를 가질 때만 쓰이기를 원한다. 그래야 화면의 색을 보고 처리해야 할 상태를 즉시 구분할 수 있다.

#### 수용 기준

1. THE 콘솔_시각_체계 SHALL 중립_계조를 가장 밝은 단계부터 가장 어두운 단계까지 순서를 부여한 정확히 6개의 단계로 정의한다.
2. THE 콘솔_시각_체계 SHALL 중립_계조 단계 값을 `--foreground`, `--muted-foreground`, `--muted`, `--border`, `--card`, `--background` 토큰과 불투명도 조합으로만 파생하고, 16진수 색상 리터럴과 `rgb` 함수 표기와 채도가 0이 아닌 `hsl` 함수 표기를 단계 값으로 사용하지 않는다.
3. THE 콘솔_시각_체계 SHALL 상태_색상 역할을 오류, 경고, 성공 3개로 한정한다.
4. THE 콘솔_시각_체계 SHALL 상태_색상 역할마다 정확히 1개의 색상 토큰을 배정하고, 오류 역할에 `--destructive` 토큰을 배정한다.
5. WHEN 데이터_시각화가 2개 이상 6개 이하의 계열을 표시할 때, THE 데이터_시각화 SHALL 계열마다 서로 다른 중립_계조 단계 1개를 배정한다.
6. WHERE 표시 대상이 오류, 경고, 성공 중 하나의 상태를 나타내는 경우에만, THE 관리자_콘솔 SHALL 상태_색상 토큰을 사용하고, 계열 구분과 장식 목적에는 상태_색상 토큰을 사용하지 않는다.
7. THE 사이드바 SHALL 섹션 배지 표기를 섹션 4개 전체에 동일한 중립_계조 단계 1개로 제공하고, 배지 텍스트와 사이드바 배경 사이 명암비를 4.5:1 이상으로 유지한다.
8. THE 사이드바 SHALL 활성 메뉴_항목 강조를 중립_계조 대비로 제공하고, 활성 항목 채움과 비활성 항목 배경 사이 명암비를 3:1 이상, 활성 항목 라벨과 활성 항목 채움 사이 명암비를 4.5:1 이상으로 유지한다.
9. THE 모듈_셸 SHALL 머리말 제목과 머리말 아이콘을 동일한 중립_계조 단계 1개의 단색으로 제공하고, 그라디언트 채움과 투명 텍스트 채움을 사용하지 않으며, 제목 텍스트 명암비를 4.5:1 이상, 아이콘 명암비를 3:1 이상으로 유지한다.
10. THE 관리자_콘솔 SHALL 제어 요소의 채움과 경계선을 중립_계조 단계 값으로 제공하고, 채움 또는 경계선과 인접 배경 사이 명암비를 3:1 이상으로 유지한다.
11. THE 데이터_시각화 SHALL 인접한 두 중립_계조 단계의 명도 차이를 8퍼센트포인트 이상으로 유지하고, 계열 도형의 채움 또는 경계선과 카드 배경 사이 명암비를 3:1 이상으로 유지한다.
12. THE 관리자_콘솔 SHALL 기존 의존성 목록만 사용한다.
13. THE 관리자_콘솔 SHALL 참조 컴포넌트 라이브러리 패키지를 의존성에 추가하지 않는다.
14. THE 검증_스위트 SHALL 데이터_시각화 계열 색 지정에 16진수 색상 리터럴, `rgb`·`rgba` 함수 표기, 채도가 0이 아닌 `hsl`·`hsla` 함수 표기, 색조 이름을 포함한 유틸리티 클래스 이름의 4개 부류가 모두 없음을 단정한다.
15. THE 검증_스위트 SHALL 콘솔 셸 소스의 색상 사용이 중립_계조 6개 단계 값과 상태_색상 3개 토큰으로 구성된 허용 목록에 한정됨을 단정하고, 허용 목록 밖 색상 사용이 1건 이상이면 실패한다.
16. IF 데이터_시각화가 7개 이상의 계열을 표시하면, THEN THE 데이터_시각화 SHALL 직접 라벨, 표식 형태, 채움 패턴 중 1개 이상을 중립_계조 외 계열 구분 수단으로 함께 제공한다.
17. IF 경고 역할 또는 성공 역할에 배정할 색상 토큰이 콘솔_시각_체계에 정의되어 있지 않으면, THEN THE 관리자_콘솔 SHALL 해당 상태를 중립_계조 단계와 한국어 상태 문자열로만 표시하고 색조 리터럴을 사용하지 않는다.
18. FOR ALL 상태_색상 사용 지점, THE 관리자_콘솔 SHALL 색상과 같은 자리에 한국어 상태 문자열 또는 표식 형태를 함께 제공한다.

### 요구사항 10: 데이터 시각화 형태와 운영 질문 대응

**사용자 스토리:** 관리자로서, 화면의 도표가 내가 실제로 답을 찾는 질문에 대응하기를 원한다. 그래야 장식용 그래프를 지나쳐 필요한 판단 근거만 읽을 수 있다.

#### 수용 기준

1. THE 데이터_시각화 SHALL 데이터 시각화 대응표의 (메뉴 ID, 시각화 형태) 조합 11개마다 카드 1개를 제공하고, 표에 없는 조합은 제공하지 않는다.
2. THE 데이터_시각화 SHALL 각 시각화마다 대응표의 답하는 운영 질문 1개를 60자 이내 한국어 문장 1개로, 카드 최초 표시 시점부터 마우스 이동이나 초점 이동 없이 표시한다.
3. THE 데이터_시각화 SHALL 각 시각화마다 대응표의 근거 데이터 출처 이름을 40자 이내 문자열로 같은 카드 안에 표시하고, 제공자 진단 정보와 데이터베이스 내부 식별자는 표시하지 않는다.
4. WHERE 메뉴_항목이 데이터 시각화 대응표에 없는 경우, THE 모듈_패널 SHALL 데이터_시각화 개수를 0으로 유지한다.
5. WHEN 데이터_시각화의 모든 계열에 대한 근거 데이터 점 개수 합이 0일 때, THE 데이터_시각화 SHALL 사전 정의된 고정 한국어 빈 상태 안내 문장 1개를 표시하고 도형 렌더링을 생략한다.
6. IF 데이터_시각화의 근거 데이터 요청이 실패하거나 응답이 형식 검증을 통과하지 못하면, THEN THE 데이터_시각화 SHALL 사전 정의된 고정 한국어 오류 문구 1개를 표시하고, 도형 렌더링을 생략하며, 제공자 오류 원문과 응답 상태 값을 표시하지 않는다.
7. THE 데이터_시각화 SHALL 도형으로 표현한 모든 계열의 이름과 값을 같은 카드 안 문자열로, 도형과 같은 단위 및 같은 반올림 자릿수로, 마우스 이동이나 초점 이동 없이 제공한다.
8. THE 데이터_시각화 SHALL 도형 영역의 최상위 요소를 `aria-hidden` 상태로 제공하고, 도형 영역 안에 초점 가능한 요소를 두지 않으며, 문자열 요약을 보조 기술이 읽는 텍스트로 제공한다.
9. THE 검증_스위트 SHALL 데이터 시각화 대응표의 메뉴 ID와 시각화 형태 조합 11개가 정확히 일치함, 대응표에 없는 6개 메뉴_항목의 데이터_시각화 개수가 0임, 그리고 승인 출처 없는 목표 기준값 상수가 소스에 없음을 단정한다.
10. IF 리뷰 검수 목표 기준값에 운영자 승인 출처가 없으면, THEN THE 데이터_시각화 SHALL `reviews` 불릿 바의 목표 표식을 렌더링하지 않고, 기본값이나 추정 목표 기준값을 코드에 두지 않으며, 목표 기준 미승인을 알리는 고정 한국어 문장 1개를 같은 카드 안에 표시한다.
11. IF 데이터_시각화의 근거 데이터 점 개수가 형태별 최소 점 개수(KPI 스파크라인 카드, 범위 밴드 영역, 워터폴 델타 단계, 활동 히트맵, 컴팩트 스파크라인 행은 2개, 그 외 형태는 1개) 미만이면, THEN THE 데이터_시각화 SHALL 도형 렌더링을 생략하고 문자열 요약과 고정 한국어 안내 문장 1개만 표시한다.
12. WHEN 데이터_시각화의 계열 중 1개 이상이 형태별 최소 점 개수를 충족하고 1개 이상의 계열이 데이터 점 0개일 때, THE 데이터_시각화 SHALL 빈 상태로 처리하지 않고 최소 점 개수를 충족한 계열만 중립_계조로 렌더링하며, 데이터 점 0개인 계열 이름을 문자열 요약에 표시한다.

### 요구사항 11: 카드 기하와 메타 표기 규칙

**사용자 스토리:** 관리자로서, 카드의 모양과 하단 표기가 화면마다 같기를 원한다. 그래야 어떤 값이 요약 수치인지 눈으로 바로 찾을 수 있다.

#### 수용 기준

1. THE 콘솔_시각_체계 SHALL 카드 반경, 제어 반경, 표식 반경 3단계로만 이루어진 모서리 반경 척도를 정의하고 각 단계에 정확히 1개의 값을 배정한다.
2. THE 콘솔_시각_체계 SHALL 카드 반경을 24픽셀로 정의하고 데이터_시각화 카드의 네 모서리 전부에 동일한 값으로 적용한다.
3. THE 콘솔_시각_체계 SHALL 표식 반경을 표식 높이의 2분의 1 이상으로 정의하여 표식 좌우 끝이 완전 원형이 되게 한다.
4. THE 콘솔_시각_체계 SHALL 카드 경계선 두께와 카드_메타_행 상단 구분선 두께를 각각 1픽셀로 정의한다.
5. WHEN 데이터_시각화가 막대 계열을 표시할 때, THE 데이터_시각화 SHALL 막대 끝 모서리 반경을 4픽셀로 적용한다.
6. WHEN 데이터_시각화가 선 계열 또는 호 계열을 표시할 때, THE 데이터_시각화 SHALL 선 끝 마감과 선 연결부 전부를 둥근 형태로 적용하고 각진 마감을 사용하지 않는다.
7. WHERE 데이터_시각화 카드가 표시되는 경우, THE 데이터_시각화 SHALL 카드_메타_행 정확히 1개를 카드 경계선 내부의 최하단에 배치하고 상단 구분선으로 도형 영역과 분리한다.
8. THE 카드_메타_행 SHALL 왼쪽 설명 문자열 1개와 오른쪽 강조 값 문자열 1개를 한 줄에 좌우 양 끝으로 배치하고 행 높이를 16픽셀 이상으로 유지한다.
9. THE 카드_메타_행 SHALL 고정폭 글꼴과 11픽셀 글자 크기를 사용하고 문자열과 배경의 명암비를 4.5:1 이상으로 유지한다.
10. THE 카드_메타_행 SHALL 오른쪽 강조 값의 숫자 문자를 동일한 문자 폭으로 표시하고 값이 갱신되어도 오른쪽 정렬 기준선과 소수점 위치를 유지한다.
11. THE 카드_메타_행 SHALL 왼쪽 설명 문자열을 24자 이내 한국어로 표시한다.
12. THE 검증_스위트 SHALL 카드 반경 24픽셀, 제어 반경 12픽셀, 표식 반경 조건, 경계선 두께 1픽셀, 막대 끝 반경 4픽셀 값과 카드_메타_행의 왼쪽 설명 문자열·오른쪽 강조 값 존재를 단정한다.
13. THE 콘솔_시각_체계 SHALL 제어 반경을 12픽셀로 정의한다.
14. IF 막대 두께가 막대 끝 모서리 반경의 2배보다 작으면, THEN THE 데이터_시각화 SHALL 해당 막대의 끝 모서리 반경을 그 막대 두께의 2분의 1로 축소한다.
15. IF 왼쪽 설명 문자열의 표시 폭이 카드_메타_행의 가용 폭을 초과하면, THEN THE 카드_메타_행 SHALL 왼쪽 설명 문자열만 말줄임으로 축약하고 오른쪽 강조 값 전체를 축약 없이 표시한다.

### 요구사항 12: 밝기 모드 대응과 동작 축소

**사용자 스토리:** 야간에 작업하는 관리자로서, 다크 모드에서도 모든 도표를 같은 정보량으로 읽기를 원한다. 그래야 조명 환경에 따라 판단 근거가 달라지지 않는다.

#### 수용 기준

1. WHILE 라이트 모드인 동안, THE 데이터_시각화 SHALL 중립_계조를 라이트 모드 토큰에서만 파생하고, 표시 계열 수와 같은 개수의 서로 구분되는 계조 단계를 사용한다.
2. WHILE 다크 모드인 동안, THE 데이터_시각화 SHALL 중립_계조를 다크 모드 토큰에서만 파생하고, 표시 계열 수와 같은 개수의 서로 구분되는 계조 단계를 사용한다.
3. FOR ALL 데이터_시각화 표면, 같은 데이터 집합을 기준으로 라이트 모드와 다크 모드에서 표시되는 계열 수, 계열 식별 라벨 집합, 계열별 데이터 점 개수 SHALL 같다.
4. WHEN 관리자가 밝기 모드를 전환할 때, THE 관리자_콘솔 SHALL 현재 경로를 유지한 상태에서 활성 메뉴_항목, 이미 조회된 데이터, 적용된 검색 문자열과 필터 선택을 그대로 유지하고 새 데이터 요청을 발행하지 않는다.
5. WHEN 관리자_콘솔이 새 브라우저 세션에서 처음 표시될 때, THE 관리자_콘솔 SHALL 저장된 밝기 모드 선택 값을 첫 화면 그리기 전에 적용하여 다른 밝기 모드가 적용된 화면이 한 프레임도 표시되지 않게 한다.
6. WHEN 표시 대상 집합이 바뀔 때, THE 모듈_그리드 SHALL 변경 입력이 확정된 시점부터 200밀리초 이내에 전환을 완료하고 최종 표시 대상만 남긴다.
7. WHERE 사용자 환경이 동작 축소를 선호하는 경우, THE 관리자_콘솔 SHALL 전환 애니메이션과 골격 화면 반복 애니메이션을 생략하고 중간 단계 표시 없이 최종 상태를 표시한다.
8. WHEN 마우스 지시자가 데이터_시각화의 계열 영역에 진입할 때, THE 데이터_시각화 SHALL 해당 계열의 식별 라벨과 현재 값을 포함하는 값 안내를 한 번에 하나만 표시한다.
9. WHEN 마우스 지시자가 데이터_시각화의 계열 영역을 벗어날 때, THE 데이터_시각화 SHALL 해당 계열의 값 안내를 제거하고 계열 표시 상태를 진입 이전과 같게 되돌린다.
10. WHEN 데이터_시각화의 계열 요약 제어가 키보드 초점을 받을 때, THE 데이터_시각화 SHALL 마우스 지시자 진입 시와 동일한 식별 라벨과 값을 포함하는 값 안내를 표시한다.
11. THE 검증_스위트 SHALL 라이트 모드와 다크 모드 양쪽에서 모든 데이터_시각화 표면의 계열 수 일치를 단정하고, 어느 한 표면에서라도 계열 수가 다르면 실패로 처리한다.
12. IF 저장된 밝기 모드 선택 값이 없거나 라이트, 다크, 시스템 중 어느 값과도 일치하지 않으면, THEN THE 관리자_콘솔 SHALL 시스템 밝기 설정을 따르는 모드를 적용하고 그 값을 저장된 선택 값으로 기록한다.
13. WHERE 사용자 환경이 동작 축소를 선호하는 경우, WHEN 표시 대상 집합 또는 밝기 모드가 바뀔 때, THE 관리자_콘솔 SHALL 동작 축소를 선호하지 않는 환경과 동일한 최종 표시 대상, 밝기 모드, 값 안내 내용을 제공한다.
14. WHILE 값 안내가 표시되는 동안, WHEN 관리자가 Esc 키를 누를 때, THE 데이터_시각화 SHALL 값 안내를 제거하고 키보드 초점을 값 안내를 띄운 계열 요약 제어에 유지한다.

### 요구사항 13: 모듈 카드 그리드 탐색

**사용자 스토리:** 신규 관리자로서, 콘솔에 어떤 화면이 있고 각각 무엇을 하는지 한 화면에서 훑어보기를 원한다. 그래야 사이드바 제목만 보고 짐작하지 않는다.

#### 수용 기준

1. WHEN 대시보드 (KPI)가 활성화될 때, THE 모듈_그리드 SHALL 메뉴_레지스트리에 정의된 15개 메뉴_항목 전부를 메뉴_레지스트리 정의 순서대로 카드로 표시한다.
2. THE 모듈_그리드 SHALL 카드마다 메뉴_레지스트리의 표시 제목, 목적 문장, 섹션 이름, 대표 작업 이름 네 항목 전부를 빈 문자열이 아닌 값으로 표시한다.
3. WHEN 관리자가 검색 입력에 64자 이내의 확정된 문자열을 입력할 때, THE 모듈_그리드 SHALL 앞뒤 공백을 제거한 문자열을 대소문자 구분 없이 표시 제목 또는 목적 문장의 부분 문자열로 비교하여 일치하고 현재 섹션 필터 조건도 함께 충족하는 카드만 표시한다.
4. WHEN 관리자가 섹션 필터에서 섹션 하나를 선택할 때, THE 모듈_그리드 SHALL 선택된 섹션에 배치되고 현재 검색 문자열 조건도 함께 충족하는 카드만 표시한다.
5. WHEN 표시 카드 수가 바뀔 때, THE 모듈_그리드 SHALL 현재 표시 카드 수와 전체 15를 포함한 한국어 문장을 200밀리초 이내에 `aria-live="polite"` 영역으로 알린다.
6. IF 검색 문자열과 섹션 필터를 함께 적용한 결과 카드 수가 0이면, THEN THE 모듈_그리드 SHALL 카드 영역 대신 한국어 빈 상태 안내 문장과, 실행 시 검색 문자열을 빈 문자열로 되돌리고 섹션 필터 선택을 해제하는 필터 해제 제어를 표시한다.
7. WHEN 관리자가 카드의 대표 작업 제어를 실행할 때, THE 메뉴_라우터 SHALL 해당 카드 메뉴_항목의 정규_링크로 이동하여 그 메뉴_항목을 활성 상태로 만든다.
8. THE 모듈_그리드 SHALL 검색 입력과 섹션 필터 제어 각각에 한국어 라벨을 프로그램적으로 연결한다.
9. THE 모듈_그리드 SHALL 뷰포트 폭 767픽셀 이하에서 1열, 768픽셀 이상 1279픽셀 이하에서 2열, 1280픽셀 이상에서 3열 카드 배치를 사용하며 360픽셀 폭에서 가로 스크롤을 발생시키지 않는다.
10. THE 모듈_그리드 SHALL 카드의 대표 작업 제어 접근성 이름에 해당 카드의 표시 제목과 대표 작업 이름을 모두 포함한다.
11. FOR ALL 검색 문자열과 섹션 필터 조합, 모듈_그리드가 표시하는 카드 수 SHALL 0 이상 15 이하이다.
12. WHERE 검색 문자열이 빈 문자열이거나 공백만으로 구성되고 섹션 필터가 선택되지 않은 경우, THE 모듈_그리드 SHALL 15개 카드 전부를 표시한다.
13. FOR ALL 검색 문자열과 섹션 필터 조합, 표시된 카드의 메뉴 ID 집합 SHALL 메뉴_레지스트리의 메뉴 ID 집합의 부분집합이다.
14. WHILE 검색 입력에서 한글 입력 조합이 진행 중인 동안, THE 모듈_그리드 SHALL 조합이 확정되지 않은 문자를 필터 조건에서 제외하고 직전 확정 문자열의 결과 집합을 유지한다.
15. WHILE 대시보드 (KPI)가 활성화된 동안, THE 모듈_그리드 SHALL 대시보드 (KPI) 지표 요약 영역 다음 위치에 배치되어 뷰포트 1280×768픽셀의 초기 스크롤 위치에서 지표 요약 영역이 계속 표시되도록 유지한다.
16. FOR ALL 검색 문자열 A와 A를 접두사로 갖는 검색 문자열 B, 동일한 섹션 필터 값에서 B에 대해 표시된 카드 집합 SHALL A에 대해 표시된 카드 집합의 부분집합이다.

### 요구사항 14: 접근성과 키보드 운용

**사용자 스토리:** 보조 기술을 사용하는 관리자로서, 마우스 없이 사이드바 전체를 사용하기를 원한다. 그래야 다른 관리자와 같은 업무를 수행할 수 있다.

#### 수용 기준

1. THE 사이드바 SHALL 접힌 데스크톱 상태, 펼친 데스크톱 상태, 모바일 드롭다운 상태 각각에서 15개 메뉴_항목 선택 제어 전부를 포인터 입력 없이 도달 가능한 순차 키보드 초점 순서에 화면 표시 순서와 같게 포함한다.
2. WHEN 메뉴_항목 선택 제어가 키보드 초점을 받을 때, THE 사이드바 SHALL 두께 2픽셀 이상이고 인접 배경과 명도 대비 3:1 이상인 초점 표시를 라이트 모드와 다크 모드 양쪽에서 렌더링한다.
3. WHILE 사이드바가 접힌 상태인 동안, THE 사이드바 SHALL 메뉴_항목이 초점 또는 마우스 진입을 받은 후 120밀리초 이내에 표시 제목 안내를 표시하고 초점 이탈 또는 마우스 이탈 후 120밀리초 이내에 그 안내를 제거한다.
4. THE 사이드바 SHALL 15개 메뉴_항목 전부에 같은 문서에 렌더링된 작업 영역 식별자와 정확히 일치하는 `aria-controls` 값을 부여한다.
5. WHEN 관리자가 문서 진입 후 Tab 키로 초점을 이동할 때, THE 관리자_콘솔 SHALL 건너뛰기 링크를 첫 초점 정지로 두고 이후 사이드바, 작업 영역, 모듈 작업 제어 순서로 초점을 이동한다.
6. WHERE 사용자 환경이 동작 축소를 선호하는 경우, THE 사이드바 SHALL 접힘·펼침 전환, 모바일 드롭다운 열기·닫기, 순서 이동 표현의 애니메이션 지속 시간을 0밀리초로 적용하고 최종 상태를 상태 변경 직후 첫 렌더 결과로 표시한다.
7. THE 사이드바 SHALL 자신을 빈 문자열이 아닌 한국어 접근성 이름을 가진 탐색 랜드마크로 노출하고, 15개 메뉴_항목 선택 제어 각각에 표시 제목을 포함한 빈 문자열이 아닌 한국어 접근성 라벨을 제공한다.
8. WHEN 순서 편집 상태가 바뀔 때, THE 사이드바 SHALL 편집 제어의 `aria-pressed` 값을 켜짐이면 `true`, 꺼짐이면 `false`로 설정하고 잠김 여부를 포함한 현재 상태를 aria-live 영역으로 1회 알린다.
9. THE 관리자_콘솔 SHALL 상태_색상으로 구분한 표시마다 오류, 경고, 성공 중 해당하는 역할을 나타내는 한국어 문자열 표식을 같은 표시 영역 안에 함께 제공한다.
10. WHILE 순서 편집이 켜진 상태인 동안, WHEN 관리자가 항목 이동 제어 또는 섹션 이동 제어를 키보드로 활성화할 때, THE 사이드바 SHALL 포인터 끌기 없이 대상 메뉴_항목 또는 섹션을 한 칸 이동하고 활성화한 제어에 초점을 유지한다.
11. WHILE 모바일 드롭다운이 열린 상태인 동안, THE 사이드바 SHALL 순차 키보드 초점을 드롭다운 내부의 초점 가능 요소로만 한정하고 마지막 요소 다음 초점을 첫 요소로 되돌린다.
12. WHEN 모바일 드롭다운이 Esc 입력, 메뉴_항목 선택, 드롭다운 외부 활성화 중 하나로 닫힐 때, THE 사이드바 SHALL 초점을 드롭다운 열기 제어로 되돌린다.

### 요구사항 15: 반응형 동작

**사용자 스토리:** 이동 중인 관리자로서, 모바일에서도 사이드바 메뉴 전체에 도달하기를 원한다. 그래야 현장에서 급한 검수를 처리할 수 있다.

#### 수용 기준

1. WHILE 화면 폭이 768픽셀 이상이고 사이드바가 접힌 상태인 동안, THE 사이드바 SHALL 15개 메뉴_항목의 아이콘만 표시하고 표시 제목과 섹션 이름 문자열은 표시하지 않는다.
2. WHEN 관리자가 사이드바 펼침 제어를 실행할 때, THE 사이드바 SHALL 200밀리초 이내에 메뉴_항목의 표시 제목과 섹션 이름을 표시하고, 그 펼침 상태를 현재 화면 표시 세션 동안 현재 장치에서만 유지한다.
3. WHILE 화면 폭이 767픽셀 이하인 동안, THE 사이드바 SHALL 15개 메뉴_항목 전부를 하나의 드롭다운 목록으로 제공하고 목록 항목 수를 15로 유지한다.
4. WHEN 모바일 드롭다운에서 메뉴_항목이 선택될 때, THE 사이드바 SHALL 200밀리초 이내에 드롭다운을 닫고 선택된 메뉴_항목을 활성 상태로 표시한다.
5. WHILE 화면 폭이 767픽셀 이하인 동안, THE 관리자_콘솔 SHALL 하단 탐색의 표시 여부와 무관하게 하단 탐색 높이와 하단 안전 영역 값의 합 이상인 여백을 작업 영역 아래에 유지한다.
6. THE 모듈_셸 SHALL 화면 폭 360픽셀 이상에서 내용 스크롤 폭이 화면 폭을 넘지 않는 상태로 표시 제목과 요약 문장을 표시한다.
7. THE 사이드바 SHALL 메뉴_항목 선택 제어의 최소 높이를 36픽셀 이상으로 유지하고, 화면 폭 360픽셀에서도 이 값을 줄이지 않는다.
8. THE 데이터_시각화 SHALL 화면 폭 360픽셀 이상에서 내용 스크롤 폭이 화면 폭을 넘지 않는 상태로 카드_메타_행을 한 줄로 표시한다.
9. WHEN 관리자_콘솔 화면이 새로 적재될 때, THE 사이드바 SHALL 이전에 저장된 펼침 선택 값의 존재 여부나 읽기 성공 여부와 무관하게 접힌 상태로 시작한다.
10. WHILE 화면 폭이 768픽셀 이상 1279픽셀 이하인 동안, THE 사이드바 SHALL 드롭다운 대신 세로 목록과 펼침 제어를 표시한다.
11. THE 검증_스위트 SHALL 화면 폭 767픽셀과 768픽셀에서의 사이드바 표현 전환을 단정하고, 메뉴_항목 선택 제어 최소 높이 36픽셀이 포인터 목표 크기 하한 24픽셀 이상이며 상향 목표 44픽셀에는 미달함을 단정한다.

### 요구사항 16: 한국어 표기 일관성

**사용자 스토리:** 관리자로서, 같은 개념이 화면마다 같은 낱말로 표기되기를 원한다. 그래야 인수인계와 운영 문서 작성이 쉬워진다.

#### 수용 기준

1. THE 메뉴_레지스트리 SHALL 표시 제목, 목적 문장, 담당 업무, 대표 작업 이름에서 음식점 개체를 맛집, 사용자 신규·수정 제출물을 제보, 데이터 정확성 판정 활동을 검수, 맛집 사이 이동 안내를 동선으로 표기하고, 같은 개념에 다른 낱말을 함께 쓰지 않으며, 개별 건의 처리 동작 이름으로만 승인과 반려를 사용한다.
2. THE 사이드바 SHALL 메뉴_항목의 표시 제목을 공백, 소괄호, 로마자 문자를 모두 포함한 유니코드 문자 수로 세어 14자 이내로 표시한다.
3. THE 관리자_콘솔 SHALL 위험_작업_절차 단계 이름을 미리보기, 확인, 적용, 재확인, 감사 기록 5개 문자열로 이 순서대로 표기하고, 사전 검토, 승인, 반영, 검증, 로그를 단계 이름으로 쓰지 않는다.
4. IF 모듈_패널이 오류 상태를 표시해야 하면, THEN THE 모듈_패널 SHALL 같은 오류 유형에 항상 같은 고정 한국어 문구를 표시하고, 제공자와 데이터 저장소의 원문 메시지, 예외 이름, 요청 본문 값을 그 문구에 포함하지 않는다.
5. THE 관리자_콘솔 SHALL 섹션 이름을 판단, 검수, 운영, 콘텐츠 제작 4개 문자열로만 표기하고, 홈과 실험실을 섹션 이름으로 표시하지 않는다.
6. THE 관리자_콘솔 SHALL 모델생성 산출물의 제목 또는 인접 표식에 초안 또는 제안 중 하나의 낱말을 표시하고, 확정, 사실, 완성, 최종을 그 산출물 표기에 쓰지 않는다.
7. THE 관리자_콘솔 SHALL 상태_색상 역할 이름을 오류, 경고, 성공 3개 문자열로 표기하고, 위험, 주의, 정상을 역할 이름으로 쓰지 않는다.
8. THE 검증_스위트 SHALL 사이드바 메뉴 제목 15개와 섹션 이름 4개를 개수와 문자열 전체 일치로 단정하고, 15개 제목이 서로 중복되지 않으며 각 제목의 문자 수가 14자 이내이고 그중 최대 길이가 10자임을 단정한다.
9. FOR ALL 15개 메뉴_항목, THE 관리자_콘솔 SHALL 사이드바 목록, 모듈_패널 머리말, 활성 메뉴 표시에서 메뉴_레지스트리에 보관된 같은 표시 제목 문자열을 표시한다.
10. WHERE 표시 제목 또는 섹션 이름에 로마자 문자가 포함되는 경우, THE 메뉴_레지스트리 SHALL KPI와 OCR 두 개 대문자 약어만 허용하고, 그 밖의 로마자 낱말은 한글 음절 표기로 보관한다.
11. IF 표시 제목 또는 섹션 이름 문자열이 메뉴_레지스트리 값과 다르거나 식당, 음식점, 업소, 가게, 신청, 문의, 심사, 경로, 루트 중 하나를 포함하면, THEN THE 검증_스위트 SHALL 해당 시험을 실패로 판정한다.

### 요구사항 17: 관리자 API 가드레일

**사용자 스토리:** 서비스 운영자로서, 관리자 메뉴가 사용하는 모든 서버 경로가 권한 확인과 고정 응답 규칙을 따르기를 원한다. 그래야 권한 없는 접근과 내부 정보 노출을 막을 수 있다.

#### 수용 기준

1. WHEN 관리자_API가 요청을 받을 때, THE 관리자_API SHALL 요청 본문 파싱, 권한 있는 서버 전용 저장소 클라이언트 생성, 저장소 호출, 외부 호출 중 어느 것보다 먼저 관리자 권한 확인을 수행한다.
2. IF 관리자 권한 확인이 실패하면, THEN THE 관리자_API SHALL 요청 본문 파싱과 데이터 접근을 생략하고 미인증 상태와 권한 없음 상태를 서로 다른 고정 코드로 구분한 응답을 반환한다.
3. IF 데이터 저장소 또는 외부 제공자 오류가 발생하면, THEN THE 관리자_API SHALL 제공자 진단 정보, 저장소 오류 문장, 호출 추적 정보를 제외하고 고정 한국어 문구와 공백 없는 64자 이내 고정 오류 코드를 포함한 응답을 반환한다.
4. WHEN 관리자_API가 변경 요청을 받을 때, THE 관리자_API SHALL 동일 출처 검증을 먼저 수행하여 통과한 요청만 처리하고 검증에 실패한 요청은 저장소 상태를 변경하지 않은 채 고정 코드 응답으로 거부한다.
5. WHEN 관리자_API가 요청 본문을 읽을 때, THE 관리자_API SHALL 해당 경로에 상수로 선언된 최대 바이트 상한을 적용하여, 상한을 넘는 본문을 빈 본문이나 기본값으로 대체하지 않고 저장을 생략한 고정 코드 응답으로 거부한다.
6. THE 관리자_API SHALL 목록 응답 항목 수를 소스에 상수로 선언된 최대 상한 이하로 유지하고, 요청의 항목 수 매개변수가 그 상한보다 크면 상한값으로 절단하며, 매개변수가 없으면 선언된 기본값을 적용한다.
7. THE 관리자_API SHALL 성공 응답과 오류 응답 모두에 `Cache-Control: no-store` 헤더를 포함한다.
8. THE 관리자_API SHALL 크롤링, 미디어 변환, 대량 생성 모델 호출, 외부 드라이브 작업, 대량 적재 작업을 라우트 처리기 안에서 직접 실행하지 않고 `backend` 실행 경로에 위임한다.
9. THE 검증_스위트 SHALL 메뉴_항목이 사용하는 관리자_API 경로마다 권한 확인 호출이 본문 파싱과 권한 있는 서버 전용 저장소 클라이언트 생성과 저장소 호출보다 소스 순서에서 앞섬, 고정 코드 응답, 열거된 고정 상태 코드 집합, `Cache-Control: no-store` 헤더를 단정한다.
10. IF 관리자 권한 확인이 성공하지 않았으면, THEN THE 관리자_API SHALL 권한 있는 서버 전용 저장소 클라이언트를 생성하지 않고 저장소 호출과 외부 호출을 수행하지 않는다.
11. THE 관리자_API SHALL 응답 상태 코드를 소스에 열거된 고정 집합 안의 값으로만 사용하고, 그 집합에 없는 상태 코드를 응답에 도입하지 않는다.
12. IF `backend` 실행 경로 호출 또는 외부 제공자 호출이 소스에 상수로 선언된 최대 대기 시간 10초 이내에 완료되지 않으면, THEN THE 관리자_API SHALL 해당 호출을 중단하고 고정 코드 응답을 반환한다.

### 요구사항 18: 위험 작업 절차 적용

**사용자 스토리:** 관리자로서, 삭제나 공개 노출 변경 같은 되돌리기 어려운 작업 전에 영향 범위를 먼저 확인하기를 원한다. 그래야 실수를 되돌릴 수 없는 상태로 만들지 않는다.

#### 수용 기준

1. WHERE 메뉴_항목이 restaurants(삭제·복구), submissions(반려), reviews(삭제 후보), users(권한 변경·비활성화), banners·map-overlays·routes(공개 노출 변경), pipeline(실행 요청) 중 하나인 경우, THE 모듈_패널 SHALL 위험_작업_절차의 5단계를 미리보기 → 확인 → 적용 → 재확인 → 감사 기록 순서로 전부 적용하고 어떤 단계도 생략하지 않는다.
2. WHEN 관리자가 위험 작업을 시작할 때, THE 모듈_패널 SHALL 해당 작업의 미리보기 식별 해시, 영향 대상 총 건수(0 이상의 정수), 대상 목록 최대 50건, 그리고 미리보기 생성 시각으로부터 600초 뒤인 만료 시각을 표시한다.
3. WHEN 미리보기가 표시된 후, THE 모듈_패널 SHALL 미리보기 식별 해시와 함께 전송되는 확인 문구를 선행·후행 공백과 대소문자까지 정확히 일치하도록 직접 입력할 것을 요구하고, 확인 입력값을 미리 채우지 않는다.
4. WHEN 확인 입력이 미리보기 값과 정확히 일치하고 미리보기 식별 해시가 만료되지 않았을 때, THE 관리자_API SHALL 적용을 1회 수행하고 적용 후 다시 조회한 대상 상태와 실제 반영 건수를 재확인 값으로 응답한다.
5. IF 확인 입력이 미리보기 값과 일치하지 않으면, THEN THE 관리자_API SHALL 적용을 중단하고 어떤 대상 상태도 변경하지 않은 채 고정 코드 응답을 반환하며, 동일 미리보기 식별 해시에서 불일치가 누적 3회 발생하면 해당 해시를 무효화한다.
6. WHEN 적용이 완료될 때, THE 감사_기록기 SHALL 단일 작업 식별자, 대상 식별자, 상태, UTC 기준 시각, 미리보기 식별 해시를 추가 전용으로 1건 기록하고, 개인정보_경계가 금지한 값(자격 증명, 세션 토큰, 이메일, 전화번호, 원문 요청 본문, 제공자 진단 메시지)은 기록하지 않는다.
7. IF 적용이 실패하면, THEN THE 감사_기록기 SHALL 동일 작업 식별자로 실패 상태와 고정 오류 코드를 추가 전용으로 기록하고, 제공자 원문 오류 메시지는 기록하지 않는다.
8. WHILE 위험 작업이 진행 중인 동안, THE 모듈_패널 SHALL 위험_작업_절차 5단계 중 현재 단계와 이미 완료된 단계를 관리자에게 표시한다.
9. IF 적용 요청의 미리보기 식별 해시가 존재하지 않거나 만료되었거나 대상 상태가 미리보기 생성 시점과 달라졌으면, THEN THE 관리자_API SHALL 적용을 중단하고 대상 상태를 변경하지 않은 채 고정 코드 응답을 반환하며 새 미리보기 생성을 요구한다.
10. WHEN 동일한 미리보기 식별 해시로 적용 요청이 2회 이상 도착할 때, THE 관리자_API SHALL 최초 요청만 적용하고 이후 요청에는 추가 상태 변경 없이 최초 적용의 재확인 값을 반환하며 감사 기록을 중복으로 추가하지 않는다.
11. FOR ALL 수용 기준 1에 열거된 메뉴_항목, THE 검증_스위트 SHALL 미리보기 표시, 확인 불일치 차단, 적용 후 재확인, 감사 기록, 만료·중복 요청 차단에 대한 통과/실패 단정을 각각 포함한다.

### 요구사항 19: 개인정보 및 로그 경계

**사용자 스토리:** 개인정보 담당자로서, 관리자 메뉴 화면과 서버 로그에 민감 값이 남지 않기를 원한다. 그래야 관리자 콘솔이 개인정보 노출 경로가 되지 않는다.

3. WHEN 관리자_API가 오류를 기록할 때, THE 관리자_API SHALL 메뉴 ID 또는 도메인 이름, 작업 이름, 고정 오류 코드, 기록 시각 4개 항목만 기록한다.
4. WHERE 메뉴_항목이 사용자 계정 정보를 표시하는 경우, THE 모듈_패널 SHALL 계정 식별자, 표시 이름, 권한 역할, 계정 상태, 계정 생성 시각, 최근 로그인 시각, 이메일 확인 여부, 개인정보_경계가 생성한 이메일 마스킹 표식 8개 항목만 표시한다.

7. THE 검증_스위트 SHALL 관리자_콘솔 소스와 관리자_API 소스에서 금지 부류 12개의 표시 경로와 기록 경로가 없음을 소스 계약 시험으로 단정한다.

10. WHEN 검증_스위트가 이 요구사항의 화면 표시 규칙을 브라우저 시험으로 확인할 때, THE 검증_스위트 SHALL 표 원문과 관리자_API 응답 본문 원문을 제외한 마스킹 표식 존재 여부만 증거로 저장한다.

### 요구사항 20: 감사 범위 진실성

5. THE 모듈_패널 SHALL 개인정보 사고 대응 화면으로 이동하는 링크 1개를, 자동 신고 완료나 처리 완료를 주장하지 않는 설명 문구와 함께 표시한다.

8. IF 관리자 변경 도메인이 응답의 감사 범위 목록에 없으면, THEN THE 모듈_패널 SHALL 해당 도메인을 감사_기록기 미적용으로만 표기한다.
9. IF 감사 기록 보존 기간이 승인된 보존 클래스 값으로 응답에서 확인되지 않으면, THEN THE 모듈_패널 SHALL 보존 기간 확인 필요 상태만 표시하고 보존 기간 값을 표시하지 않는다.

9. **콘솔 셸 색조 제거**(요구사항 9-7 ~ 9-10): `getSidebarBadgeClassName`의 섹션별 앰버·스카이·바이올렛·에메랄드, 활성 메뉴의 `bg-primary`, `AdminEmbeddedModuleShell` 제목의 `bg-gradient-primary bg-clip-text text-transparent`, 머리말 아이콘의 `text-primary`가 모두 변경 대상입니다. `data-admin-sidebar-badge-tone` 속성 값 규칙도 함께 바뀝니다.
10. **모듈 카드 그리드 신설**(요구사항 13): 검색과 섹션 필터를 갖는 15개 카드 그리드가 대시보드 (KPI)에 추가됩니다.
11. **시각화 신설 항목**(요구사항 10): 반원 게이지 호, 범위 밴드 영역, 계조 누적 막대, 워터폴 델타 단계, 단계 퍼널, 불릿 바, 활동 히트맵, 컴팩트 스파크라인 행이 대응표 기준으로 추가됩니다. 대응표에 없는 6개 메뉴(`map-overlays`, `banners`, `routes`, `users`, `storyboard`, `youtube-thumbnail-generator`)에는 시각화를 추가하지 않습니다.
12. **카드 기하 통일**(요구사항 11): 카드 반경 24픽셀, 표식 완전 원형, 둥근 막대 끝과 선 끝, 고정폭 11픽셀 카드_메타_행이 데이터_시각화 카드 전체에 적용됩니다.

## 열린 사항

설계 단계에서 확정할 항목입니다. 요구사항 자체를 막지 않으나 구현 전 결정이 필요합니다.

1. **리뷰 검수 목표값 출처**(요구사항 10, 불릿 바): 목표 표식의 기준값을 어디서 가져올지 정해야 합니다. 운영자 승인 없는 임의 목표값은 코드에서 만들지 않습니다.
2. **상태_색상 토큰 배정**: 오류 역할은 기존 `--destructive`를 사용할 수 있습니다. 경고와 성공 역할에 배정할 토큰을 새로 정의할지, 기존 토큰을 재사용할지 결정해야 합니다. 경고와 성공 토큰이 배정되기 전까지는 요구사항 9-17이 대체 표시 동작을 규정합니다.
3. **`framer-motion` 도입 여부**(요구사항 12-6): 현행 관리자 콘솔은 Tailwind `motion-reduce:*`만 사용합니다. 모듈_그리드 전환을 CSS 전환으로 처리할지 이미 설치된 `framer-motion`을 사용할지 결정해야 합니다. 어느 쪽이든 새 의존성은 추가하지 않습니다.
4. **`insights` 화면과 대시보드 (KPI) 중복 범위**: 두 메뉴가 같은 `/api/admin/youtube-kpis`를 1차 출처로 사용합니다. 각 화면이 답하는 질문의 경계를 설계에서 분리해야 합니다.
