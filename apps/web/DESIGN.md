# 쯔동여지도 Web 디자인 계약

## 모바일 리뷰 작성 OCR 플로우

1. **영수증 증거는 항상 재확인 가능해야 한다.**
   - `AI 입력 · 확인 필요` 배지는 단순 상태 표시가 아니라 첨부한 영수증 증거 뷰어를 여는 액션이다.
   - 영수증 파일이 없으면 배지는 비활성 상태로만 표시하고, 사용자가 근거 확인 가능 여부를 오해하지 않게 한다.

2. **영수증 사진은 1단계에서 뷰포트 기준으로 충분히 커야 한다.**
   - 기본 미리보기는 모바일에서 `clamp(320px, 52dvh, 620px)` 수준의 세로 공간을 확보한다.
   - 사용자가 사진을 누르거나 `크게 보기`를 누르면 전체 화면 증거 뷰어로 전환한다.

3. **증거 뷰어는 OCR 보정 도구다.**
   - 전체 화면, 닫기, 확대, 축소, 초기화 액션을 제공한다.
   - 확대 상태에서는 드래그로 위치를 조정할 수 있어야 한다.
   - 뷰어를 닫아도 첨부 파일이나 입력 상태는 변경하지 않는다.

4. **1/2/3단계는 전체 화면 폼 셸 안에서 동작한다.**
   - 헤더/단계 표시/푸터는 고정 영역이고, 단계별 본문만 독립 스크롤한다.
   - 모바일 키보드나 안전 영역 때문에 CTA가 입력칸을 덮지 않도록 푸터는 shrink 영역으로 둔다.
   - 배경 지도나 이전 화면이 깜빡여 보이지 않도록 모바일 셸은 `100dvh` 기반의 불투명 배경을 유지한다.

5. **AI 자동 입력은 사용자의 수동 입력을 이기면 안 된다.**
   - 사용자가 입력 중이거나 단계를 직접 이동했다면 자동 이동은 억제한다.
   - 자동 입력 하이라이트는 충분히 보이되, 일정 시간 후 사라져야 한다.

6. **3단계는 글쓰기 우선이다.**
   - 리뷰 내용을 먼저 확인/작성하고, 음식 사진은 그 아래에서 첨부한다.
   - 리뷰 textarea는 뷰포트 기준 최소 높이를 확보해 SSE 자동 입력이 보이게 한다.

7. **검증 기준**
   - 영수증 첨부 후 1단계 미리보기와 전체 화면 뷰어가 모두 보여야 한다.
   - AI 배지에서 같은 영수증 증거를 열 수 있어야 한다.
   - 2단계 방문 정보와 3단계 리뷰 자동 이동은 기존 수동 보호 규칙을 유지해야 한다.
   - Samsung Browser/Chrome Android/iOS Safari 폭에서 헤더, 본문, 푸터가 빈 공간 없이 맞물려야 한다.
