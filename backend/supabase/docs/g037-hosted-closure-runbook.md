# G037 hosted migration closure runbook

## Authority, scope, and hard stops

GitHub Actions is read-only for G037. It is dispatch-only from the exact detached SHA of protected `main`, uses the `g037-hosted-closure` concurrency group, and permits only source `validate` plus remote `preflight`, `readback`, `runtime-probe`, and `reconciliation-readback`. `validate` is the default and has no credentials. Never run production execution or any production apply in Actions; Actions has no private signing-key, authorization, recovery, or freeze-evidence path.

The controller binds the current commit to the authoritative G034 manifest: exactly 28 migrations, in its pinned order and hashes. G026 and versions `20260713002500`, `20260713002600`, and `20260713002700` are excluded and must never enter the selected ledger. `public.restaurants_backup` absence is a hard preflight stop. G035 receipts are recovery evidence only; they do not authorize production execution. G036 recovery closure must be bound before local execution.

Do not retry a self-committing migration with an ambiguous commit result. Stop, preserve sanitized receipt hashes, and investigate through provider support and human operators. Do not infer success from a timeout, disconnect, or partial receipt.

## Human-only prerequisites

Before any remote read-only preflight or local production execution, a human must maintain the human-only provider/ingress fence and quiescence: disable or block all application, worker, dashboard, API, direct-SQL, and provider ingress writes; verify no in-flight writers; and independently verify that the human-only G037 write freeze is already active (`G037_WRITE_FREEZE=active`). An absent or mismatched freeze state blocks execution. This local-only procedure must not set or change `G037_WRITE_FREEZE` or any GitHub repository or environment variable. Operators must keep the freeze active through G038. Do not make any post-G037 claim that live account deletion or retention has resumed.

A human must collect fresh provider evidence for PITR/database recovery, Auth metadata/state recovery, Storage metadata recovery, and Storage/blob recovery RPO. Keep authorization, recovery, RPO, freeze, service, recipient, and signing-key materials in owner-restricted offline evidence/key paths. Backup material, provider exports, credentials, raw URLs, row data, keys, and secrets never go to GitHub repositories, Actions artifacts, caches, logs, arguments, releases, or issues. This procedure has a zero-cost/no-paid-service boundary: use no paid service or new paid backup destination.

Perform and record an offline rollback rehearsal before production execution. Keep only sanitized G036-bound recovery evidence with the closure record.

## Protected sequence

1. On the controlled local host, independently verify the already-active human-only G037 write freeze and collect exactly five fresh owner-restricted residual-evidence artifacts: no owner write, no dashboard write, no provider write, no out-of-band write, and producer stop. An absent or mismatched freeze state blocks execution; do not set or change `G037_WRITE_FREEZE` or any GitHub repository or environment variable.
2. Run `g037_production_controller.py prepare` only through the isolated exact-source bootstrap. It publishes a fresh canonical **unsigned** assertion request outside the repository after rollback-only preflight. Each of the five evidence files must use the G037 residual-evidence schema and name its exact channel and freeze ID. Producer-stop must contain exactly the `account-deletion-worker.yml` / `dispatch` and `privacy-retention.yml` / `retain` identities, their literal `vars.G037_WRITE_FREEZE != 'active'` guard, `guard_active: true`, and `no_in_flight: true`; missing, added, renamed, or swapped producers block.
3. Review the exact request bytes offline, create a detached signature with the fixed authorization public-key counterpart, and retain request and signature as distinct restrictive regular files. Run `finalize` through the same bootstrap; it holds both files by descriptor, verifies the detached signature over the held canonical request bytes, and publishes the finalized assertion. Never supply any private signing-key path on the controller command line.
4. Verify under restrictive external custody the legacy G035 capture, restore, and inspection receipts and the legacy signed authorization. Confirm their signature, ordered chain, manifest, remediation vector, and receipt hashes before proceeding.
5. Build and sign the G037 remediation template offline as its detached-signature ceremony specifies. Keep all private keys outside the controller CLI and under restrictive external custody.
6. `validate`, `rehearse`, and `execute` require the same seven legacy/execution files: legacy G035 capture receipt, restore receipt, inspection receipt, legacy authorization, legacy authorization signature, G037 execution authorization template, and its detached signature.
7. Run local-only `g037_production_controller.py validate` through the isolated bootstrap with the finalized operator assertion and all seven files. Validate is database-free and rejects custody, expiry, source, freeze, and evidence mismatches.
8. Run local-only `g037_production_controller.py rehearse` with fresh outside-repository receipt destinations. It remains rollback-only rehearsal evidence, but it atomically consumes that execution authority in the canonical authorization-derived journal before opening the database. Independently verify the signed rehearsal artifacts, then obtain a fresh request, detached signature, finalized assertion, and execution authority before execute.
9. Independently verify the recovery archive and signed rehearsal artifacts. Stop on any mismatch.
10. Before execution, pre-provision the owner-restricted attempt-journal directory at `C:\ProgramData\TzudongRecovery\g037-attempts` on Windows or `/var/lib/tzudong-recovery/g037-attempts` on POSIX; the controller never creates it and never derives it from `HOME` or another caller-controlled environment variable. Run local-only `g037_production_controller.py execute`. The controller derives the only valid marker location from the authenticated authorization ID and authorization hash: the directory is fixed by the operating system and the filename is derived from the authorization, so callers cannot select or override either. The marker is exclusively created and directory-synced before secret admission or database connection, its canonical digest is bound into prepared remediation evidence plus outcome and reconcile receipts, and it is retained on commit, rollback, ambiguity, and every failure. A second process cannot reuse the authority with a different output path. After **any** attempt, including rollback, obtain fresh request, detached signature, finalized assertion, and execution authority. No GitHub Actions job may execute this mutation.
11. After execute, ALWAYS run local `g037_production_controller.py reconcile` as the required post-readback gate to verify encrypted archives and live observed terminal roots and publish reconciled final/outcome receipts. Remote `reconciliation-readback` is supplementary only; dispatch it with readback and runtime-probe on the same bound commit while retaining the provider/ingress fence and write freeze through G038.
