# Audit agent guidance

Inventory the project's active instruction files and skill metadata; read only the files that affect the requested workflow. Check host/global guidance only to explain an actual conflict, and do not edit shared plugin caches or personal memory as a project change.

Identify unconditional document loads, overly broad skill triggers, redundant approval requests, unclear completion criteria and repeated verification. Keep original requirements with real correctness or operational purpose; distinguish a source recommendation from a host requirement.

For an edit request, make the smallest useful change in an isolated candidate; for a read-only audit, return findings and proposed corrections without editing. Keep common guidance short, route domain detail by concrete task triggers, and give skills precise descriptions. Existing explicit authorization covers its original scope; unknown legal or hosted evidence remains unknown.

Verify local references and preserved requirements. Try realistic contrasting cases: copy-only work, auth/SQL changes, an already-authorized external action, and a release missing external evidence. Check which guidance is needed, what tests are relevant, and whether the agent should continue, ask, or stop. Do not call real external mutators to evaluate instruction behavior.

Finish with the inspected or edited paths, observed findings, coverage of the requested recommendations and unresolved host-level constraints. Document actual instruction-byte changes if useful; do not claim measured token, latency or model-quality gains without comparable measurements. Do not launch another audit recursively.
